## Пример 1 — Кэш, читаемый при промахе, с честным сроком жизни

Страница товара читает одни и те же несколько строк гораздо чаще, чем они меняются, и сейчас каждое чтение доходит до базы. Поставьте кэш рядом с чтением (cache-aside, кэш в стороне), наполните его при промахе и выберите срок жизни, который заявляет, насколько устаревшей может быть страница товара.

```js
async function getProduct(id) {
  return db.query("select * from products where id = $1", [id]);
}
```

### Решение

```js
async function getProduct(id) {
  const key = `product:${id}`;
  const cached = await cache.get(key);
  if (cached) return JSON.parse(cached);

  const product = await db.query("select * from products where id = $1", [id]);
  const ttl = 300;                    // секунды: максимум, на который цена может отстать от записи
  await cache.set(key, JSON.stringify(product), "EX", ttl);
  return product;
}
```

Путь чтения обращается к источнику только при промахе, поэтому кэш наполняется теми данными, которые действительно запрашивают. Пять минут — настоящее решение: оно ограничивает, как долго может отдаваться устаревшая цена, даже если инвалидацию пропустили. База остаётся единственным источником истины, поэтому потерянный ключ стоит одного запроса. Обычно же ошибаются на другом: кэшируют вообще без срока жизни, что выглядит быстрее и превращает пропущенную инвалидацию в неограниченную устарелость.

## Пример 2 — Истечение, которое приходит под нагрузкой

Главная страница читает один ключ избранного товара с фиксированным сроком жизни в час. В начале каждого часа все запросы промахиваются по нему в один и тот же момент, поэтому база получает всплеск, который кэш должен был убрать. Измените устройство так, чтобы источник видел одно чтение вместо каждого запроса.

```js
const key = "product:featured";
const ttl = 3600;                      // один фиксированный час
await cache.set(key, body, "EX", ttl);
```

### Решение

```js
const key = "product:featured";
const ttl = 3600 + Math.floor(Math.random() * 300);  // сроки жизни разнесены

// ключ всё ещё слишком горяч, чтобы дать ему истечь под нагрузкой:
// обновляет один вызывающий, а остальные читают копию, когда она появится
const gotLock = await cache.set("lock:product:featured", "1", "NX", "EX", 10);
if (gotLock) {
  const body = await db.query("select * from products where featured = true");
  await cache.set(key, JSON.stringify(body), "EX", ttl);
}
```

Разнесение срока жизни не даёт ключам, записанным в одну секунду, истечь в одну секунду, а короткая блокировка позволяет одному вызывающему заплатить за обновление, пока остальные ждут копию. Блокировка несёт собственный срок жизни, поэтому упавший обновляющий не может держать её вечно. Обычно ошибаются, считая кэш защитой и не спрашивая, что происходит при промахе: популярный ключ, истекающий под нагрузкой, делает отказ хуже, а не лучше.
