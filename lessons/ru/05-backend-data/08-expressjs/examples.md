## Пример 1 — Упорядочите цепочку, чтобы ничего не выполнялось слишком рано

У сервера есть публичный маршрут проверки работоспособности, защищённый маршрут заказов, журналирование запросов, разбор тела и центральный обработчик ошибок. В черновике ниже проверка смонтирована после маршрутов, которые она защищает, а брошенная ошибка уходит наружу. Расставьте каждую часть так, чтобы следующая могла на неё опираться.

```js
app.use(express.json());
app.get('/orders', listOrders);
app.post('/orders', createOrder);
app.use(requireAuth);            // слишком поздно: они уже выполнились
```

### Решение

```js
const app = express();
app.use(logRequests);
app.get('/health', (req, res) => res.json({ status: 'ok' }));
app.use(express.json());         // тело читают только маршруты ниже
app.use(requireAuth);            // до защищаемых маршрутов
app.get('/orders', listOrders);
app.post('/orders', createOrder);
app.use((err, req, res, next) => {
  res.status(500).json({ code: 'internal_error' });
});
```

Теперь неаутентифицированный запрос отклоняется до разбора тела, а обработчик с четырьмя аргументами стоит последним, поэтому брошенная ошибка доходит до него, а не превращается в трассировку стека. Порядок и есть проект: каждое звено может опираться только на то, что выполнилось раньше. Обычно ошибаются, монтируя проверку после маршрута, как в черновике, и оставляя асинхронному маршруту возможность уронить ошибку мимо обработчика.

## Пример 2 — Обработчик, достаточно тонкий, чтобы тестировать его без сервера

Маршрут заказа читает тело, валидирует его, считает сумму и пишет в базу — всё в одном месте. Вынесите решения в функцию от обычных данных, а обработчику оставьте перевод между запросом и этой функцией.

```js
app.post('/orders', async (req, res) => {
  const items = req.body.items;
  if (!items.length) return res.status(422).json({ code: 'empty_order' });
  let total = 0;
  for (const item of items) total += item.price * item.quantity;
  const order = await db.orders.insert({ items, total });
  res.status(201).json(order);
});
```

### Решение

```js
// create-order.js — ни запроса, ни ответа, тест вызывает напрямую
function buildOrder(body) {
  const items = body.items || [];
  if (!items.length) return { error: 'empty_order' };
  const total = items.reduce((s, i) => s + i.price * i.quantity, 0);
  return { order: { items, total } };
}

// routes.js
app.post('/orders', async (req, res) => {
  const { error, order } = buildOrder(req.body);
  if (error) return res.status(422).json({ code: error });
  res.status(201).json(await db.orders.insert(order));
});
```

Правила и арифметика теперь живут в функции от обычных значений, поэтому тест вызывает её, не занимая порт, а обработчику остаётся только то, что требует фреймворка: разобранное тело, внедрённая зависимость и код состояния. Обычно ошибаются, тестируя через настоящий сервер или рассчитывая на поле вроде аутентифицированного пользователя, когда маршрут смонтирован без промежуточного слоя, который его выставляет.
