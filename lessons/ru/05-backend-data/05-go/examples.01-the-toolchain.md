## Пример 1 — Один бинарный файл для целевой платформы

Небольшая служба заказов собирается и запускается на ноутбуке разработчика, это x86-64, а хост развёртывания — Linux на arm64. Шаг выпуска копирует то, что произвёл ноутбук. Напишите команду сборки, которая выдаёт артефакт, запускаемый на этом хосте, и скажите, что делает результат самодостаточным.

```bash
$ go build -o orders ./cmd/orders
$ ./orders
listening on port 8080          # работает на машине сборки

$ ./orders                      # после копирования на хост развёртывания
cannot execute binary file: Exec format error
```

### Решение

```bash
$ GOOS=linux GOARCH=arm64 go build -ldflags "-s -w" -o dist/orders ./cmd/orders
$ file dist/orders
dist/orders: ELF 64-bit LSB executable, ARM aarch64, statically linked   (иллюстративно)
```

Две настройки в команде называют целевую операционную систему и архитектуру, а флаги компоновщика опускают отладочную информацию, поэтому на хост копируется один небольшой файл, которому ничего не нужно установленным. Компиляция свела каждую зависимость в этот файл, поэтому образ, в который он попадает, может не содержать ничего другого. Обычно ошибаются, оставляя целевую платформу на момент выпуска: тогда сбой проявляется как ошибка формата Exec в конвейере, где пересборка дорога, а не на этапе сборки.

## Пример 2 — Дифф с одним видом изменений

Обработчик приходит с авторскими отступами, и пул-реквест переформатирует файл, одновременно меняя вычисление. Получите файл таким, каким его оставляет форматтер, и организуйте изменение так, чтобы рецензент увидел один вид различий.

```go
func Total(items []Item) Money {
    var sum Money
  for _,it:=range items {
        sum = sum.Add(it.Price)
    }
      return sum
}
```

### Решение

```go
func Total(items []Item) Money {
	var sum Money
	for _, it := range items {
		sum = sum.Add(it.Price)
	}
	return sum
}
```

Вывод форматтера детерминирован, поэтому его применение отдельным коммитом оставляет изменение поведения в диффе, где есть только это изменение, а одна и та же команда выполняется в каждом редакторе и в непрерывной интеграции. Ручное форматирование даёт обратное: проверка переписывает файл снова, и рецензенту приходится разбираться, какие различия важны.
