## Пример 1 — Пул, который всегда завершается

Задание импорта проходит по списку заказов и вызывает медленный поиск для каждого. Первая версия запускает горутину на заказ и возвращается, как только список пройден, поэтому процесс может завершиться, выполнив половину работы. Сделайте версию с фиксированным числом работников, которая возвращается только после обработки каждого заказа.

```go
for _, o := range orders {
	go enrich(o)          // никто их не ждёт
}
return nil
```

### Решение

```go
jobs := make(chan Order)
var wg sync.WaitGroup
for i := 0; i < workers; i++ {
	wg.Add(1)
	go func() {
		defer wg.Done()
		for o := range jobs {
			enrich(o)
		}
	}()
}
for _, o := range orders {
	jobs <- o
}
close(jobs)               // закрывает отправитель, никогда приёмник
wg.Wait()
```

Закрытие канала — это то, что сообщает каждому работнику, что заказов больше не будет, а группа ожидания — то, что сообщает вызывающему о завершении работы, поэтому функция возвращается только после последнего заказа. Первая версия запускает по горутине на заказ без учёта их, и каждая незавершённая держит свой стек. Обычно ошибаются приёмником, закрывающим канал, из-за чего следующая отправка вызывает панику.

## Пример 2 — Кто ждёт, когда очередь заполняется

Читатель производит события быстрее, чем писатель успевает их сохранять. Буфер добавили, чтобы сгладить всплески, а память растёт, пока процесс не убьют. Выберите буфер и политику на случай заполнения и напишите версию, которая их применяет.

```go
var events []Event
for e := range source {
	events = append(events, e)   // растёт без ограничения
	write(e)
}
```

### Решение

```go
// 32 события поглощаются без ожидания, затем производитель замедляется.
queue := make(chan Event, 32)
go writeAll(queue)

for e := range source {
	queue <- e          // при заполнении эта отправка ждёт
}
close(queue)
```

Буфер указанного размера разъединяет прибытие и обработку до этого размера; после него отправка ждёт, и читатель удерживается на скорости писателя — это осознанный выбор вместо отбрасывания событий. Неограниченный срез — не буфер побольше, а рост памяти без потолка. Обычно ошибаются, подбирая размер буфера, чтобы спрятать всплеск нагрузки, вместо того чтобы решить и записать, что происходит при заполнении.
