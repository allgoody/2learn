## Что это такое

RESTful API выставляет данные как ресурсы со стабильными адресами, а клиенты действуют над ними, опираясь на стандартные значения методов HTTP и кодов состояния. У коллекции есть адрес, у отдельного элемента — дочерний, а создание, чтение, замена и удаление отображаются на методы, которые протокол уже определяет; стиль этот — набор ограничений, а не спецификация, и следовать стоит тем его частям, которые делают API предсказуемым для того, кто не читал его документацию.

## Почему это важно

Предсказуемость и есть вся отдача: когда каждый API придумывает собственные глаголы и формат ошибок, каждая интеграция превращается в разведку, а у клиентов накапливаются особые случаи. Когда соглашения соблюдены, тот, кто знает один эндпоинт, знает и форму остальных — как перечислить ресурсы, как получить один, как создать и как выглядит сбой. Однако от соглашений зависят не только люди: чтение, которое меняет состояние, или создание, повтор которого даёт другой результат, ломают допущения, на которые опираются кэши и прокси.
