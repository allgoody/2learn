## Что это такое

Машиночитаемый документ со списком путей, методов на каждом из них, параметров, тел запросов и ответов и кодов состояния — так выглядит формат описания HTTP API. Он структурирован, а не написан прозой, поэтому один и тот же документ порождает документацию, клиентские библиотеки, заглушки сервера и тесты; OpenAPI — это формат, а Swagger — название семейства инструментов вокруг него.

## Почему это важно

Если записать интерфейс до реализации, приходится принять решения, которые иначе обнаруживают клиенты: что содержит запрос, как выглядит сбой, какие поля необязательны. Описание при этом одно, и его потребляют несколько инструментов, поэтому документация и клиентский код не разойдутся с реализацией незаметно для тестов; а когда команда строит обе стороны сервиса, спецификация становится контрактом, который позволяет им идти параллельно.
