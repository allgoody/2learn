## Пример 1 — Красный, провалившийся по неверной причине

Тест ниже написали первым, затем прогнали. Вывод показан так, как его напечатал раннер. Решите, годится ли такой красный, и дойдите до зелёного.

```text
FAIL  tests/discount.test.ts
  ● Test suite failed to run
    Cannot find module './discout' from 'tests/discount.test.ts'

test("applies five percent after five years", () => {
  expect(discountFor(customerWith({ years: 5 }))).toBe(0.05);
});
```

### Решение

```ts
// исправленный импорт; теперь провал тот, который нужен
import { discountFor } from "./discount";
// FAIL  discountFor is not defined            <- ожидаемый красный

// зелёный: простейшее, что проходит
export function discountFor(customer) {
  return 0.05;   // один случай; следующий тест требует правила
}
```

Красный из-за отсутствующего модуля ничего не доказывает о поведении — он доказывает лишь, что файл импортировали. Годный красный называет то, что вы вот-вот построите, поэтому вы знаете, что утверждение связано с кодом и действительно способно провалиться. Исправление импорта стоит минуты и покупает единственную гарантию, на которой держится весь цикл: этот тест видели провалившимся по верной причине, и он снова провалится, если поведение даст регрессию.

## Пример 2 — Модуль, который трудно тестировать

Сервис регистрации решает, истёк ли пробный период. Его тест продолжает падать в зависимости от часа запуска. Скажите, о чём говорит эта трудность, и измените код, а не утверждение.

```ts
export class Trial {
  isExpired(signupAt: Date) {
    const days = (Date.now() - signupAt.getTime()) / 86400000;
    return days > 14;
  }
}

// FAIL на некоторых прогонах: ожидалось false, получено true
```

### Решение

```ts
export class Trial {
  constructor(private readonly now: () => Date = () => new Date()) {}

  isExpired(signupAt: Date) {
    const days = (this.now().getTime() - signupAt.getTime()) / 86400000;
    return days > 14;
  }
}

test("expires after fourteen days", () => {
  const trial = new Trial(() => new Date("2026-03-20T00:00:00Z"));
  expect(trial.isExpired(new Date("2026-03-05T00:00:00Z"))).toBe(true);
});
```

Проблемой был не тест: модуль тянется к системным часам, что не даёт закрепить результат. Это давление на проектирование, и это самая крупная практическая выгода от тестов раньше кода. Внедрение часов чинит тест и улучшает класс — зависимость теперь видна в конструкторе, а не спрятана внутри метода. Делайте этот рефакторинг, пока набор зелёный, и никогда — пока он красный.
