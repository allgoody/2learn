## Пример 1 — Сообщение об ошибке, исправленной по TDD

Поддержка сообщает, что скидочный купон применяется к подарочным картам, которые всегда должны продаваться по номиналу. Исправление — защита в две строки. Покажите, в каком порядке должна идти работа, и что она оставляет после себя.

```ts
// сообщение и код, где живёт ошибка
// "на подарочные карты попадает скидка SAVE10"
function priceOf(item, coupon) {
  return item.price * coupon.rate(item);
}
```

### Решение

```ts
// 1. красный: воспроизвести, прежде чем трогать код
test("ignores coupons on gift cards", () => {
  expect(priceOf(giftCard(50), SAVE10)).toBe(50);
});
// FAIL: expected 50, received 45     <- дефект подтверждён

// 2. зелёный: наименьшая защита
function priceOf(item, coupon) {
  if (item.kind === "gift-card") return item.price;
  return item.price * coupon.rate(item);
}
```

Провалившийся тест — единственное доказательство, что ошибка существовала, и единственная защита от её возвращения; поэтому исправления ошибок и есть самый сильный случай для цикла. Написанный после исправления тест всё равно поймал бы регрессию, но он никогда не подтвердил бы диагноз, а защита, добавленная без воспроизведённого провала, — догадка о том, какое условие имело значение. Цикл здесь не церемония: он превращает отчёт в названный постоянный случай.

## Пример 2 — Связка, которую модульные тесты только делают хрупкой

Роутер регистрирует обработчики при старте. Проверяющий просит модульные тесты на порядок регистрации. Покажите, что утверждал бы такой тест и почему набор лучше покрыт в другом месте.

```ts
export function registerRoutes(router, handlers) {
  for (const h of handlers) router.add(h.method, h.path, h.fn);
}
// предполагаемый тест: expect(router.add).toHaveBeenNthCalledWith(1, "GET", "/health", fn)
```

### Решение

```ts
// интеграционный тест: запустить систему и пересечь настоящий стык
test("GET /health answers 200", async () => {
  const app = await startApp({ handlers: handlersForTest });
  const res = await app.request("/health");
  expect(res.status).toBe(200);
});
```

У функции регистрации почти нет собственного поведения — она переправляет аргументы. Модульный тест может утверждать лишь порядок вызовов, деталь реализации, которая ломается при каждой перестройке связки и ничего не доказывает о том, доходит ли запрос до обработчика. Запустите систему и сделайте запрос: вот уровень, на котором правильность связки действительно наблюдаема. Тест раньше кода — инструмент для правил и расчётов, а не налог на каждую существующую функцию.
