## Что это такое

Четыре паттерна покрывают большую часть пользы в повседневном коде: Стратегия — для подмены алгоритма; Адаптер — чтобы несовместимый интерфейс подошёл; Наблюдатель — чтобы уведомлять заинтересованных, не зная, кто они; и Фабрика — чтобы решать, какую реализацию создавать. Их стоит знать, потому что решаемые ими задачи возникают постоянно и потому что их имена позволяют команде быстро договориться о решении.

## Почему это важно

Эти четыре встречаются в любой большой кодовой базе, часто безымянными, и узнавание формы говорит, чего код пытается достичь и где он, вероятно, заболит. Написанное руками условие, выбирающее между платёжными провайдерами, — это Стратегия, которой не дали имени; обёртка, перекраивающая ответ сторонней библиотеки, — Адаптер. Их называние превращает разговор о переделке в конкретное изменение. Это ещё и паттерны, которые чаще всего применяют преждевременно, поэтому знание их цены и отличает использование от наряжания прямого вызова.

## Ключевые идеи

### Стратегия: варьируйте алгоритм за одним интерфейсом

Применяйте, когда вызывающему нужно выбрать между несколькими способами сделать одну работу, и выбор делается извне. Интерфейс стоит в точке вариации; каждая реализация — один алгоритм. Цена — один уровень косвенности и ещё один тип. Применённая преждевременно — одна реализация, никаких планов на другую, — она оказывается вызовом функции с лишними шагами.

```ts
interface PricingStrategy { price(items): number }
class RetailPricing implements PricingStrategy { /* ... */ }
class WholesalePricing implements PricingStrategy { /* ... */ }
```

### Адаптер: заставьте несовместимый интерфейс подойти

Применяйте, когда приходится потреблять то, чью форму вы не контролируете, — клиент сторонней библиотеки, легаси-модуль, — не позволяя этой форме протечь в ваш код. Адаптер переводит в обе стороны. Его ценность в том, что остальная система зависит от вашего интерфейса, поэтому замена лежащей в основе библиотеки позже становится изменением одного файла.

```ts
class StripeGateway implements PaymentGateway {
  charge(order) { return this.stripe.charges.create(toStripePayload(order)); }
}
```

### Наблюдатель: уведомляйте, не зная слушателей

Применяйте, когда одно событие должно дойти до неизвестного набора заинтересованных, а издатель не должен от них зависеть. Подписчики регистрируются, издатель уведомляет, и ни один не держит ссылку на тип другого. За чем следить — время жизни: подписчик, который никогда не отписывается, удерживает издателя живым, и это классическая утечка памяти в коде пользовательских интерфейсов.

```ts
emitter.on("order-placed", (order) => mailer.sendReceipt(order));
```

### Фабрика: решайте, какую реализацию создавать

Применяйте, когда создание объекта включает решение — конфигурацию, окружение, фича-флаг, — и это решение не должно размазываться по каждому вызывающему. Фабрика держит знание в одном месте и возвращает интерфейс. Когда реализация одна и решать нечего, конструктор проще и должен победить.

```ts
function createNotifier(config): Notifier {
  return config.email ? new EmailNotifier(config) : new SlackNotifier(config);
}
```

### Назовите альтернативу, прежде чем применять паттерн

Для каждого из них обычно есть более простая версия. Стратегия может быть функцией, переданной аргументом. Адаптер может быть функцией, перекраивающей данные. Наблюдатель может быть прямым колбэком, когда слушатель ровно один. Фабрика может быть обычным конструктором. Тянитесь к полному паттерну, когда простая версия доказанно перестала быть достаточной, и скажите почему в сообщении коммита.

## Практика

### Замените условие Стратегией

Найдите условие, выбирающее между двумя-тремя способами сделать одну работу. Выделите каждую ветвь в свою реализацию за интерфейсом, затем выбирайте между ними в месте вызова.

Готово, когда: добавление четвёртого случая означает один класс и одну строку в месте вызова, без правок внутри существующих ветвей.

### Урежьте перестроенный Адаптер

Найдите класс-обёртку с большим числом методов, чем использует любой вызывающий. Перепишите его так, чтобы он открывал только нужные вызывающим операции, а остальное делегировал прочь.

Готово, когда: у каждого метода обёртки есть хотя бы один вызывающий, а лежащая в основе библиотека упоминается ровно в одном файле.

## Частые ошибки

- **Стратегия с одной реализацией** — косвенность решает вариацию, которой нет; исправить: используйте прямой вызов, пока не появится второй случай.
- **Адаптер, протекающий обёрнутым типом** — форма сторонней библиотеки утекает в ваш код через параметры или возвращаемые значения; исправить: переводите на границе и никогда не открывайте чужой тип.
- **Наблюдатель без отписки** — слушатели накапливаются и удерживают мёртвые объекты живыми; исправить: храните ручку отписки и вызывайте её там, где кончается время жизни подписчика.
- **Фабрика как выбор по строке типа** — каждый новый случай правит фабрику, а строку не проверяет компилятор; исправить: предпочтите явное значение или реестр, в который модули добавляются сами.
- **Применение паттерна без называния простой альтернативы** — читатель не может понять, взвешивали ли сложность; исправить: скажите в коммите или комментарии, чего стоила бы прямая версия.
