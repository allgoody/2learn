## Пример 1 — Интерфейс с одной реализацией

Ревьюер видит форму ниже и спрашивает, не удалить ли её. Посчитайте реализации сегодня, скажите, что понадобится для второй, и чего будет стоить прямой вызов.

```ts
interface Notifier { send(user: User, message: string): Promise<void>; }

class EmailNotifier implements Notifier {
  async send(user, message) { await this.mailer.send(user.email, message); }
}

class AlertService {
  constructor(private notifier: Notifier) {}
  async alert(user, message) { await this.notifier.send(user, message); }
}
```

### Решение

```text
реализаций сегодня: 1

если появится Slack-версия: добавить один класс и одну строку там, где
происходит выбор. Сам интерфейс не меняется.

вместо этого прямой вызов: AlertService принимает EmailNotifier и
вызывает send() на нём. Тогда добавление Slack означает правку
AlertService и каждого другого класса, который отправляет, вместе с их
тестами.
```

Интерфейс стоит один тип и один параметр конструктора; альтернатива стоит правки у каждого вызывающего при появлении второго случая и приваривает логику оповещения к почтовику, который тесты не могут заменить. Вот компромисс, который сжимает имя, — шов, чья ценность зависит от того, вероятна ли за ним вариация. Ловушка — отвечать правилом, «удалить, одна реализация» или «оставить, Slack может понадобиться», вместо подсчёта цены изменения каждого варианта.

## Пример 2 — Условие, которому так и не дали имени

Метод ниже живёт в платёжном модуле. Скажите, какой паттерн он уже есть, и что должно измениться, прежде чем его выделение будет оправдано.

```ts
async function pay(order) {
  if (order.method === "card") {
    const res = await stripe.charges.create(toStripe(order));
    return { id: res.id, state: res.status };
  }
  if (order.method === "invoice") {
    const inv = await ledger.raiseInvoice(toLedger(order));
    return { id: inv.number, state: "open" };
  }
  throw new UnsupportedMethod(order.method);
}
```

### Решение

```text
это Стратегия без имени: один интерфейс, pay(order) -> { id, state },
выбор за вызывающим через order.method. Две ветви — две реализации, а
toStripe и toLedger — Адаптеры для чужой формы.

пока не стоит выделять: два случая в одном месте выбора. Выделяйте,
когда появится третий или когда второе место должно выбирать так же;
тогда выбор переезжает в Фабрику.
```

Назвать это стоит немедленно, потому что ревью становится «это Стратегия с двумя реализациями» вместо спора о ветвях, и два Адаптера уже показывают, почему чужие типы не должны протекать дальше. Выделение — отдельное решение, и его доказательство — третий случай или второе место выбора, а не опрятность. Ловушка — выделять на двух случаях, покупая Фабрику, интерфейс и два класса вместо шести читаемых строк.
