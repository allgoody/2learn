## Пример 1 — Подделка, вернувшая строки в другом порядке

Модульный тест проходит против подмены в памяти. Тот же сценарий на настоящем движке падает. Объясните, какое предположение выдумала подделка, и исправьте код.

```ts
// подделка: возвращает строки в порядке вставки, поэтому здесь всё проходит
test("lists orders newest first", async () => {
  const fake = { find: async () => [older, newer] };
  expect(await listOrders(fake)).toEqual([newer, older]);
});

// настоящий движок: FAIL   expected [newer, older], received [older, newer]
// в запросе нет ORDER BY; база вправе вернуть любой порядок
```

### Решение

```ts
// проверяем на стыке: то, что вернуло настоящее хранилище
test("lists orders newest first", async () => {
  const db = await freshDatabase();          // настоящий движок, своя схема
  await db.insert("orders", [older, newer]);
  expect(await listOrders(db)).toEqual([newer, older]);
});

// теперь запрос говорит то, что предполагал тест
const rows = await db.query("select * from orders order by created_at desc");
```

Список в памяти сохранял порядок вставки, потому что так делает массив JavaScript; реляционное хранилище без `ORDER BY` не обещает ничего. Это ровно тот класс предположений, ради которого существует настоящая граница, и его нельзя поймать изнутри подделки, разделяющей ваше заблуждение. Исправление принадлежит запросу, а не тесту: тест сформулировал контракт, нужный вызывающему коду, а код его не выполнил.

## Пример 2 — Тест, зависящий от настенных часов

Сервис регистрации тестируется через свой репозиторий. Утверждение проходит весь день и падает у того, кто запустит набор после полуночи. Назовите недетерминированную часть и сделайте тест устойчивым.

```ts
test("counts signups in the last 24 hours", async () => {
  const repo = await freshDatabase();
  const stats = new SignupStats(repo);
  await stats.record("a@example.test");
  expect(await stats.recentCount()).toBe(1);
});

// FAIL после полуночи: expected 1, received 0
```

### Решение

```ts
const now = new Date("2026-03-01T12:00:00Z");
const repo = await freshDatabase();
const stats = new SignupStats(repo, { now: () => now });
await stats.recordAt("a@example.test", now);
expect(await stats.recentCount()).toBe(1);

// в бою ничего не передают и получают настоящие часы
new SignupStats(repo);
```

Настоящая инфраструктура выставляет каждое чтение часов в коде, и здесь это чтение спрятано внутри сервиса. Передача часов снаружи привязывает утверждение к фиксированному мгновению вместо часа, в который случайно запустился набор, — та же дисциплина, что и сортировка строк перед сравнением. Тест, падающий лишь в некоторые дни, учит команду перезапускать прогон вместо разбора, а набор, которому не доверяют, стоит меньше, чем ненаписанный.
