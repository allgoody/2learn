## Пример 1 — Глобальная фикстура, к которой привязан каждый тест

Файл подготовки вставляет пятьдесят клиентов, чтобы всё нужное любому тесту уже было на месте. Новый тест меняет одного из них, и начинает падать другой тест. Покажите настоящую цену фикстуры и замените её.

```ts
// setup.ts — выполняется один раз для всего набора
beforeAll(async () => {
  for (let i = 0; i < 50; i++) await createCustomer({ id: i, tier: "basic" });
});

// тест тихо меняет строку 3
test("upgrades a customer", async () => {
  await upgrade(3);
  expect(await tierOf(3)).toBe("gold");
});
// поздний, несвязанный тест читает строку 3 и теперь падает
```

### Решение

```ts
const customer = await createCustomer({ tier: "gold" });   // только нужное этому случаю

test("upgrades a customer", async () => {
  await upgrade(customer.id);
  expect(await tierOf(customer.id)).toBe("gold");
});

// разбор безусловен, поэтому следующий тест стартует с того же места
afterEach(async () => { await rollback(); });
```

Пятьдесят строк, не упомянутых ни в одном теле теста, связывают каждый тест со всеми ними, и отказ всплывает не там, где произошло изменение. Небольшая фабрика, вставляющая одну строку с разумными значениями по умолчанию плюс поля, важные для случая, оставляет данные видимыми там, где они используются, а радиус поражения любого теста — в нём самом. Правило не «меньше данных», а «только данные этого теста», созданные в тесте и удалённые после, независимо от того, прошёл он или упал.

## Пример 2 — Очистка, выполняющаяся только на выходе

Тест вставляет строки, затем проверяет. Когда утверждение падает, строки выживают, и следующий прогон видит данные предыдущего. Исправьте разбор и строку подключения рядом с ним.

```ts
const db = await connect("postgres://admin@shared-db.internal/app");

test("creates an invoice", async () => {
  await db.insert("invoices", invoice);
  expect(await db.count("invoices")).toBe(1);   // FAIL: к третьему дню их уже 3
});
```

### Решение

```ts
const url = process.env.TEST_DATABASE_URL ?? "postgres://localhost/app_test";
const db = await connect(url);

beforeEach(async () => { await db.exec("drop schema public cascade; create schema public;"); });
afterEach(async () => { await db.exec("drop schema public cascade; create schema public;"); });

test("creates an invoice", async () => {
  await db.insert("invoices", invoice);
  expect(await db.count("invoices")).toBe(1);
});
```

Очистка должна быть безусловной, потому что именно упавший тест и оставляет за собой состояние, — а разбор, написанный после утверждения, не выполнится в том прогоне, который был важен. Построение схемы с нуля каждый раз заодно проверяет настоящие миграции, поэтому сломанная миграция падает здесь, а не во время выпуска. И строка подключения принадлежит конфигурации с безопасным локальным значением по умолчанию: жёстко вписанный общий хост — в одном копировании от записи туда, где это имеет значение.
