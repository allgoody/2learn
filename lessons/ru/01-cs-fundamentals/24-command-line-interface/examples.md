## Пример 1 — Разрушительная команда прямо из результатов поиска

Разработчик вставляет однострочник из найденного ответа, заменив только путь. Он выполняется, и результат оказывается не тем, что ожидалось. Объясните, чего здесь не хватило терминалу, затем покажите привычку, которая это предотвращает.

```bash
# из результата поиска, написанного для другой раскладки репозитория
rm -rf $(grep -rl "TODO" src/)
# вывод: пусто. код возврата: 0, потому что rm отработал успешно
```

### Решение

```bash
grep -rl "TODO" src/          # сначала посмотреть список совпадений
grep -rl "TODO" src/ | wc -l  # посчитать до удаления чего-либо
grep -rl "TODO" src/ | xargs rm   # теперь решение осознанное
```

Поскольку каждый инструмент читает текст и пишет текст, вывод можно проверить как данные до того, как с ним что-то сделали, и эта одна привычка превращает необратимый класс случайностей в задержку на несколько секунд. Необходимость её дают две детали: `grep`, завершившийся с ненулевым кодом и пустым выводом, выглядит в точности как корректный пустой результат, поэтому `rm` может молча ничего не сделать или удалить неожиданный набор файлов. Чтение справки для того инструмента, который у вас есть, вместо доверия команде, написанной для другой версии, — та же дисциплина, к которой запись призывает для всего, что удаляет или перезаписывает.

## Пример 2 — Команда, набранная в третий раз за неделю

Инженер снова набирает один и тот же длинный вызов, чтобы посмотреть, над чем работал. Это медленно и приводит к ошибкам, и каждый раз он набирает его по памяти. Скажите, какую привычку здесь просят применить, затем примените её.

```bash
# набрано по памяти, третий раз за неделю
git log --since="1 week ago" --author="$(git config user.name)" --oneline
```

### Решение

```bash
# ~/bin/weekly  — именованный скрипт лучше вызова в шестьдесят символов
#!/bin/sh
# список моих коммитов за последнюю неделю
git log --since="1 week ago" --author="$(git config user.name)" --oneline

# для короткого случая достаточно псевдонима
alias ll='ls -alh'
```

В первый раз длинная команда разовая; во второй — скрипт. Имя с комментарием вспоминается быстрее, чем сам вызов, запускается из любого каталога, как только попало в путь поиска, и даёт следующему читателю — часто тому же человеку месяцы спустя — однострочное объяснение того, что она делает. Дополняющая привычка — искать в истории вместо повторного набора: она переиспользует команду точно так, как она выполнялась, а не так, как запомнилась. Вместе они составляют большую часть того, что отличает удобного пользователя терминала от беглого.
