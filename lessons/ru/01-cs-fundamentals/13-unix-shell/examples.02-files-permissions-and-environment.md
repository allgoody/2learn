## Пример 1 — Скрипт, который не запускается

Развёртывание немедленно падает с `Permission denied` на скрипте, который прекрасно работает, если передать его интерпретатору. В листинге ниже показан файл и его каталог. Скажите, какого бита не хватает, приведите исправление и назовите изменение, которое вы делать не стали бы.

```bash
ls -l deploy.sh
# -rw-r--r-- 1 deploy deploy 218 deploy.sh
./deploy.sh
# bash: ./deploy.sh: Permission denied

ls -ld releases
# drw-rw-r-- 2 deploy deploy 4096 releases
cd releases
# bash: cd: releases: Permission denied
```

### Решение

```bash
chmod +x deploy.sh        # исполнение для владельца, группы и остальных
chmod +x releases         # каталогу нужен бит исполнения, чтобы в него войти

# не это: chmod 777 deploy.sh
```

Чтение прав слева направо даёт владельцу чтение и запись, но не исполнение, поэтому голый `./deploy.sh` отвергается, а `bash deploy.sh` работает — интерпретатору нужно лишь прочитать файл. У каталога тот же пробел в другом месте: без бита исполнения на каталоге сквозь него ничего не пройдёт, поэтому `cd` там падает. Ловушка — тянуться к правам на запись для всех, чтобы обойти ошибку, что дало бы каждой учётной записи на машине право переписать скрипт развёртывания.

## Пример 2 — Работает в терминале, падает в планировщике

Ночной скрипт правильно запускается из интерактивной оболочки и падает под планировщиком с `command not found`. Оба окружения напечатаны ниже. Скажите, какая переменная отличается и почему, затем приведите исправление.

```bash
# интерактивная оболочка
echo "$PATH"
# /home/deploy/.local/bin:/usr/local/bin:/usr/bin:/bin
which backup-tool
# /home/deploy/.local/bin/backup-tool

# плановая задача
echo "$PATH"
# /usr/bin:/bin
backup-tool
# backup-tool: command not found
```

### Решение

```bash
# назовите программу по полному пути внутри задачи
/home/deploy/.local/bin/backup-tool

# или задайте нужное задаче в начале скрипта
PATH="/usr/local/bin:/usr/bin:/bin:/home/deploy/.local/bin"
export PATH
```

Короткое имя команды ищется обходом каталогов в `PATH` по порядку, а плановая задача стартует с минимальным окружением, а не с тем, которое построила ваша интерактивная оболочка, поэтому личного каталога в списке просто нет. Назвать полный путь или задать путь там, где его прочитает сама задача, делает скрипт независимым от того, какая оболочка его запустила. Ловушка — добавить запись в интерактивный файл конфигурации, который планировщик никогда не читает: тогда исправление будто работает при проверке вручную и снова падает следующей ночью.
