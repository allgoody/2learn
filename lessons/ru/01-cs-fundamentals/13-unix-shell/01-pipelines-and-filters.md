## Что это такое

У каждой команды в конвейере есть входной поток, поток вывода и отдельный поток для ошибок, а труба соединяет вывод одной команды со вводом следующей. Фильтр — команда, которая читает текст и пишет преобразованный текст, и большая часть силы оболочки идёт от комбинирования фильтров, а не от какого-то одного инструмента. Статус завершения — нуль при успехе, не нуль при неудаче — вторая половина модели, и именно он позволяет командам принимать решения.

## Почему это важно

Стиль композиции — причина, по которой оболочка пережила все попытки её заменить. Новому графическому инструменту приходится реализовывать каждую функцию; новому фильтру командной строки достаточно делать одну вещь, и он сразу сочетается со всем остальным. Чтение конвейера точно говорит, что было сделано с данными и в каком порядке, — это и документация, и операция одновременно. Как только это щёлкнет, однострочники оболочки перестанут выглядеть заклинаниями и начнут выглядеть короткими программами.

## Ключевые идеи

### Три потока, каждый делает одно

Стандартный ввод — откуда команда читает, стандартный вывод — куда пишет результаты, стандартный поток ошибок — куда пишет диагностику. Разделение ошибок означает, что результаты можно направить куда-то по трубе, а ошибки всё равно дойдут до терминала — ровно то, что нужно, когда длинная задача выдаёт результат. Перенаправление отправляет поток в файл, и разница между перезаписью и дописыванием — один символ.

```bash
sort names.txt > sorted.txt      # перезапись
sort names.txt >> history.txt    # дописывание
grep error app.log 2> err.txt    # ошибки в файл, совпадения на экран
```

### Труба передаёт вывод одной команды следующей

Труба — это вся идея целиком: напишите каждый шаг как небольшое преобразование и соедините их. Один конвейер может фильтровать, сортировать, считать и форматировать без временных файлов и без скриптов. Стройте его слева, запуская после каждого добавления, чтобы видеть промежуточный результат и сразу ловить ошибку.

```bash
cut -d, -f2 orders.csv | sort | uniq -c | sort -rn | head -5
```

### Словарь фильтров невелик и универсален

Горстка фильтров покрывает большинство работы с текстом. Один выбирает строки по шаблону, один вырезает столбцы, один сортирует, один схлопывает соседние дубликаты, один считает, один берёт первые или последние строки, один заменяет текст. Раз каждый читает из стандартного ввода, они сочетаются в любом порядке, и выучить шесть хорошо лучше, чем шестьдесят плохо.

```bash
grep -i "error" app.log | wc -l        # посчитать совпавшие строки
awk -F, '{ sum += $3 } END { print sum }' sales.csv   # просуммировать столбец
sed 's/old-name/new-name/g' file.txt  # заменить все вхождения
```

### Коды возврата превращают команды в условия

Команда сообщает об успехе нулём, а о неудаче — чем угодно другим, поэтому то же соглашение встречается в каждом языке, который её оборачивает. Оболочка может строить цепочки на этом: запустить следующую команду, только если эта сработала, или только если она провалилась. Скрипты и конвейеры CI построены ровно из этого, и потому хорошо воспитанная программа обязана возвращать осмысленный статус, а не всегда преуспевать.

```bash
make build && run-tests || echo "сборка или тесты провалились"
grep -q "ERROR" app.log; echo "код возврата $?"
```

### Композиция с переменными и подстановкой команд

Вывод команды может стать аргументом другой команды, а оболочка умеет хранить значения в переменных. Здесь конвейер вырастает в небольшой скрипт. Заключайте переменные в кавычки, когда они могут содержать пробелы, и предпочитайте короткий скрипт всё более хитроумному однострочнику, как только конвейеру нужны цикл или условие.

```bash
today=$(date +%F)
tar -czf "backup-$today.tar.gz" ./data
```

## Практика

### Соберите отчёт одним конвейером

Из файла журнала или CSV получите пять самых частых значений одного столбца, с числом рядом с каждым. Начинайте от файла и добавляйте по одному фильтру, запуская конвейер после каждого шага.

Готово, когда: итоговый конвейер печатает пять строк, в каждой значение и его количество, и вы можете назвать вклад каждого этапа.

### Сделайте команду с двумя потоками

Запустите команду, вывод которой вы сохраняете, а ошибки уходят в файл, затем запустите вторую команду, которая выполняется, только если первая преуспела.

Готово, когда: ошибки в файле, успешный вывод дошёл до экрана, а условная команда повела себя так, как требовал её статус завершения.

## Частые ошибки

- **Сборка длинного конвейера за один раз** — ошибка в любом месте даёт уверенный неверный ответ; исправить: добавляйте по одному этапу и проверяйте промежуточный вывод.
- **Игнорирование кодов возврата** — пустой вывод провалившейся команды читается как достоверный результат; исправить: связывайте через `&&` или проверяйте статус явно.
- **Переменные без кавычек** — значение с пробелом становится двумя аргументами, и команда тихо делает не то; исправить: заключайте в кавычки каждое раскрытие переменной.
- **Путаница перезаписи и дописывания** — `>` уничтожает прежнее содержимое файла; исправить: прочитайте оператор перенаправления, прежде чем запускать команду.
- **Однострочник, которому нужен абзац для объяснения** — следующий читатель не сможет безопасно его изменить; исправить: положите его в скрипт с именем и комментарием.
