## Что это такое

Структура — это порядок, в котором читатель встречает вещи: что идёт первым, где живут детали, как устроен файл. Обработка ошибок — это структура, применённая к несчастливому пути: решение о том, где сбой обнаружен, где он превращается в решение и где перестаёт быть проблемой вызывающего. Чистый код во многом и есть привычка держать обычный путь видимым, а путь отказа — явным.

## Почему это важно

Большинство производственных ошибок не в алгоритме; они в разрыве между тем, как код читается, и тем, что машина делает на краях. Проглоченное исключение превращает ясный сбой в загадку в двух системах отсюда. Функция, которая перехватывает ошибку, чтобы продолжать, и возвращает правдоподобное значение по умолчанию, — это то, как неверное число доходит до клиента. Порядок тоже важен: код, перемешивающий проверку, преобразование и сохранение, — источник наполовину применённого изменения. Верная структура — это то, что делает путь отказа тем, о чём можно рассуждать, а не на что надеяться.

## Ключевые идеи

### Один уровень абстракции на функцию

Не смешивайте сетевой вызов, обрезку строки и запись в базу в одном блоке. Каждая строка функции-координатора должна быть вызовом примерно того же уровня, а детали — вынесены в именованные помощники. Тогда читатель может доверять сводке и спускаться лишь туда, куда ему нужно.

```ts
async function publishDraft(draft) {
  const validated = validateDraft(draft);
  const record = toRecord(validated);
  await repository.save(record);
  return record.id;
}
```

### Сбой там, где есть информация

Обрабатывайте ошибку на уровне, который знает, что с ней делать. Низкоуровневая функция должна точно сообщить, что пошло не так; средний слой — добавить контекст, который есть только у него; слой, владеющий операцией, решает, повторять, заменять или отказываться. Ранний перехват ошибки с возвратом смутного значения уничтожает информацию, нужную всем выше.

```ts
try {
  await paymentGateway.charge(order);
} catch (cause) {
  throw new PaymentFailed(`order ${order.id}`, { cause });
}
```

### Пусть счастливый путь течёт вниз

Защитные условия лучше вложенных ветвлений. Проверяйте неверные случаи первыми и выходите сразу, чтобы следующий код был обычным случаем на одном уровне отступа. Глубокая вложенность — это место, где читатель теряет, в каком сочетании условий он находится, и начинает вносить неверные правки.

```ts
function discountFor(customer) {
  if (!customer) return 0;
  if (!customer.active) return 0;
  return customer.years * 0.01;
}
```

### Не проглатывайте и не перехватывайте лишнее

Пустой блок catch — это обещание, что программа продолжит работать правильно, хотя она не знает, почему сбойнула. Перехват широкой категории ошибок и обращение с ними всеми одинаково — та же проблема в большем костюме. Перехватывайте то, что понимаете, и пусть всё остальное идёт вверх вместе со своей исходной причиной.

```ts
try {
  return JSON.parse(raw);
} catch {
  return null;   // приемлемо только потому, что null — настоящее, обработанное значение
}
```

### Ошибки — это значения, которые можно проектировать

Выброшенное исключение, возвращённый тип-результат или явное поле ошибки — всё это выборы с последствиями. Выброшенная ошибка невидима в сигнатуре и легко забывается. Возвращаемый результат вынуждает вызывающего с ним разобраться и делает сбой частью задокументированного вывода функции. Выбирайте осознанно, держитесь одного выбора в пределах модуля и не позволяйте двум соглашениям протекать в одну цепочку вызовов.

## Практика

### Переупорядочьте одну функцию ради читателя

Возьмите длинную функцию, которая проверяет, вычисляет и сохраняет. Переупорядочьте её так, чтобы неверные случаи были защищены вначале, вычисление стояло посередине за ясным именем, а сохранение было последним оператором.

Готово, когда: обычный путь читается сверху вниз без вложенности глубже одного уровня, а поведение не изменилось.

### Сделайте проглоченный сбой видимым

Найдите в своём коде блок catch, возвращающий значение по умолчанию. Добавьте исходную причину к тому, что выбрасывается или пишется в журнал, и дайте сбою имя, говорящее, какая операция не удалась.

Готово, когда: принудительный сбой этого вызова даёт сообщение, называющее операцию и нижележащую причину.

## Частые ошибки

- **Перехват ошибки только чтобы записать её и продолжить** — программа идёт дальше в неизвестном состоянии, и ущерб всплывает позже; исправить: явно решите, может ли вызывающий продолжать, и если нет — перебросьте ошибку с контекстом.
- **Возврат значения по умолчанию при сбое** — правдоподобный ноль или пустой список скрывают сломанную операцию; исправить: возвращайте результат, который вызывающий обязан истолковать, или падайте громко.
- **Смешение проверки, работы и сохранения в одном блоке** — сбой на середине оставляет частичный эффект; исправить: разделите фазы, чтобы порядок стал виден.
- **Вложенные условия вместо защитных** — читатель вынужден держать все сочетания сразу; исправить: выходите сразу для неверных случаев.
- **Исключения для обычного потока** — отсутствующее необязательное значение становится дорогим и шумным событием; исправить: возвращайте значение для ожидаемых исходов, а исключения оставьте исключительному.
