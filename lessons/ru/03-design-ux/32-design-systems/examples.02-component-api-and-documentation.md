## Пример 1 — Одна таблица свойств из пяти реальных мест вызова

Команда собирается добавить кнопку в библиотеку компонентов. Пять мест вызова уже используют самодельные версии со своими свойствами, и каждое передаёт разную комбинацию. Соберите применения и спроектируйте наименьший набор именованных вариантов. Сделайте таблицу свойств, которая их заменит.

```text
Места вызова в продукте
  основное действие в шапке страницы   "Сохранить изменения"
  второстепенное действие в диалоге    "Отмена"
  удаление аккаунта                    "Удалить аккаунт"
  действие в строке таблицы            иконка + "Изменить"
  ссылка в стиле кнопки                "Смотреть отчёт"
```

### Решение

```text
Свойство   Значения                              По умолчанию   Примечание
variant    primary | secondary | danger | link   primary        именованный набор, без свободного булева
size       small | medium | large                medium         независим от варианта
icon       элемент                              нет            необязательная иконка слева
loading    логическое значение                  false          документированное состояние

Отвергнуто: large, ghost, icon-only, full-width как булевы значения; они
складываются в кнопки, которых никто не рисовал. icon-only становится
size="small" + icon + без метки.
```

Четыре именованных варианта покрывают все пять мест вызова, а комбинации, которых никто не рисовал, выразить нельзя. Строка об отвергнутом важна не меньше таблицы: без неё следующая команда предложит пятое булево значение. Обычный провал — добавлять свойство на каждое дополнительное пожелание места, пока в интерфейсе не станет двенадцать переключателей и ни капли согласованности.

## Пример 2 — Страница, которая останавливает первый форк

Кнопка выпущена, и дизайнер просит разрушительное действие, которое на самом деле не разрушительное. Напишите короткую страницу документации: состояния для показа и строки «делайте» и «не делайте». Сделайте фрагмент, который потребитель прочитает вместо форка.

```text
Запрос
  «Нам нужна красная кнопка для "Архивировать проект". Не разрушительное,
   но должно выделяться. Можете добавить ещё один вариант?»
```

### Решение

```text
Кнопка

Состояния
  по умолчанию  метка, основная заливка
  загрузка      метка заменена индикатором, элемент отключён
  отключена     приглушённая заливка, нет отклика на нажатие

Делайте
  используйте variant="danger" для действия, которое нельзя отменить
  используйте variant="primary", когда это единственное главное действие на экране
Не делайте
  используйте variant="danger" для важного основного действия
  не форкайте локальную кнопку из-за нехватки варианта; заявите случай вместо этого

Решение
  архивация обратима, поэтому использует variant="secondary". Вариант
  danger зарезервирован за удалением, и именно это зарезервированное
  значение заставляет его всё ещё читаться как опасное.
```

Документирование состояний значит, что никто не придумает загрузку и отключённость по-своему, а «делайте» и «не делайте» отвечают на запрос про архивацию, не добавляя вариант. Зафиксированное решение — то, что не даёт вернуться тому же вопросу через квартал. Обычный провал — страница, показывающая только состояние по умолчанию: тогда потребители догадываются об остальном, и каждый догадывается по-разному.
