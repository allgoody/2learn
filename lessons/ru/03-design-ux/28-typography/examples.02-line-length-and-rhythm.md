## Пример 1 — Ограничиваем абзац на широком экране

Текст статьи заполняет всю ширину окна в 1440px, поэтому каждая строка уходит за 100 символов и читатели теряют место на переносе. Задайте меру и высоту строки так, чтобы чтение стало комфортным, не меняя в странице ничего другого.

```css
.article {
  width: 100%;
  line-height: 1.5;
}
```

### Решение

```css
.article {
  max-width: 65ch;    /* около 60-70 символов в строке */
  line-height: 1.6;   /* широкой мере нужно чуть больше */
}
```

Подсчёт символов, а не пикселей, ставит самую длинную строку около 65 и не даёт ей расти вместе с окном; чуть увеличенная высота строки помогает глазу вернуться к левому краю. Ограничение текстовой колонки — самый крупный выигрыш в читаемости из доступных на большинстве экранов. Обычная неудача — оставить `width: 100%` на большом мониторе и считать получившиеся строки в 110 символов проблемой шрифта.

## Пример 2 — Заголовок, который не принадлежит ни одному разделу

На странице ниже заголовок стоит между двумя абзацами на равном расстоянии от каждого, поэтому читается как не принадлежащий ни одному. Исправьте его промежутки из небольшой шкалы и не меняйте больше ни одного промежутка на странице.

```text
Стоимость доставки

    24px под заголовком
Основной текст ...

    24px над следующим заголовком
Возвраты

    24px под заголовком
Основной текст ...
```

### Решение

```text
Стоимость доставки

     8px под заголовком
Основной текст ...

    40px над следующим заголовком
Возвраты

     8px под заголовком
Основной текст ...
```

Теперь промежуток над заголовком в пять раз больше промежутка под ним, поэтому заголовок визуально связывается с текстом, который он вводит, и страница читается двумя ясными разделами. Оба значения берутся из одной небольшой шкалы промежутков — именно это держит ритм одинаковым от страницы к странице. Неудача, за которой надо следить, — подправить верхний промежуток только у одного заголовка: если шкала не общая, продукт начинает выглядеть собранным из частей.
