## Пример 1 — Проектирование повестки назад от решения

Группа из шести человек встречается еженедельно по вопросам регистрации и ни разу не выбрала поток. Следующая сессия забронирована на 90 минут. Превратите список тем ниже в спроектированный воркшоп: формулировка решения вверху и повестка с таймингом, по одной активности и одному результату на блок.

```text
Список приглашённых: продукт, дизайн, трое инженеров, руководитель поддержки
Название встречи: «воркшоп по регистрации»
Темы для покрытия: исследования на сегодня, идеи, технические ограничения,
обращения в поддержку, следующие шаги
Комната: забронирована на 90 минут
```

### Решение

```text
Решение: выбрать один поток регистрации для разработки в этом квартале.
Владелец: Майя. Нужно к: четвергу. Участников: 6. Комната: 90 минут.

00-05  Рамка           Прочитать решение вслух; без обсуждения.
05-20  Доказательства  Обойти пять цитат поддержки; молчаливое чтение, затем точки.
20-45  Дивергенция     4 группы x 2 скетча; подсказка: «один экран, ни одного
                       слова, которое вы не скажете вслух».
45-70  Конвергенция    Молчаливое голосование точками, затем по минуте в защиту одной точки.
70-85  Решение         Выбрать, назвать владельца, назвать первую сборку, прочитать обратно.
85-90  Закрытие        Подтвердить сверку; фотографировать только доску решений.

Результаты: подсчёт точек -> группы -> скетчи -> доска решений.
Парковка: технические ограничения, зафиксированы, но сегодня вне рамок.
```

Решение написано первым и датировано, так что повестку можно резать относительно него — технические ограничения уходят в парковку, а не съедают пятнадцать минут. Каждый блок называет активность и артефакт, который потребляет следующий блок: от цитат к точкам и к выбранному потоку. Обычная ошибка — повестка из тем: «регистрация» не активность, поэтому она растягивается на всё отведённое время, и сессия заканчивается без решения.
