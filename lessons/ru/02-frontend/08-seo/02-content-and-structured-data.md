## Что это такое

Когда страницу уже можно обойти и проиндексировать, начинается работа по её описанию — так, чтобы её поняли и выбрали. Сюда входят заголовок и описание, которые видит ищущий, структура заголовков, из которой машина понимает, о чём страница, внутренние ссылки, которые задают её контекст, и структурированные данные, способные сделать результат богаче обычной синей ссылки.

## Почему это важно

`title` — самый заметный фрагмент текста на большинстве сайтов: именно его читает ищущий, решая, кликать ли. И его же регулярно оставляют побочным продуктом шаблона. Описания и заголовки читают те же системы, что ранжируют страницу, а внутренние ссылки — главный способ, которым робот узнаёт, какие страницы важны. Структурированные данные не поднимают ранжирование напрямую, однако меняют вид результата, а от этого зависит, кликнут ли по нему вообще. Всё это дёшево написать один раз и дорого добавлять задним числом на сайте, который вырос без этого.

## Ключевые идеи

### Пишите заголовок для ищущего, а не для шаблона

Заголовок должен назвать конкретную вещь, о которой страница, а затем сайт. Вынести отличительные слова в начало важно: ищущий читает список, где начало видно, а остальное обрезано.

```html
<title>Починка протекающего радиатора — Ремонт дома</title>
<meta name="description" content="Разберитесь с протекающим радиатором, найдите отказавшее соединение и решите, стоит ли герметизировать его самостоятельно." />
```

На ранжирование описание не влияет, однако часто именно его ищущий читает вместо страницы — поэтому описывайте страницу честно, а не повторяйте в описании заголовок.

### Одна страница, одна идея, один `h1`

Структура заголовков — это план, по которому системы индексации понимают, какая часть страницы является предметом. Несколько элементов `h1` или заголовок, выбранный ради размера шрифта, размывают его. Аргумент о доступности звучит точно так же, поэтому, исправив одно, вы исправляете и другое.

### Ссылайтесь словами, описывающими назначение

Текст анкора внутренней ссылки сообщает роботу, о чём целевая страница, и подсказывает пользователю скринридера, куда ведёт ссылка, а «Читать далее» не сообщает ни того, ни другого. Описательные анкоры ничего не стоят и улучшают и то, и другое.

### Структурированные данные излагают факты в машиночитаемой форме

JSON-LD в блоке script описывает страницу как тип вместе с его свойствами: статью, товар, событие, вопрос с принятым ответом. Поисковые системы используют это для более богатых результатов и сверяют с видимым содержимым, поэтому данные должны описывать то, что страница действительно говорит.

```html
<script type="application/ld+json">
{
  "@context": "<адрес самого словаря>",
  "@type": "Article",
  "headline": "Починка протекающего радиатора",
  "datePublished": "2026-02-14",
  "author": { "@type": "Person", "name": "А. Автор" }
}
</script>
```

Значение контекста называет словарь, из которого происходят типы; здесь оно показано заглушкой, потому что этот корпус запрещает внешние ссылки в любом месте урока; настоящее значение возьмите из документации словаря.

Помечайте только те свойства, которые страница может подтвердить: разметка с рейтингом, не видимым на странице, — это нарушение, которое может стоить всех богатых результатов на сайте.

### Соответствуйте намерению за запросом

Страница о методе ранжируется по методу, а страница о покупке товара конкурирует с магазинами. Определить, на какое намерение нацелена страница, и написать её целиком под это намерение эффективнее, чем добавлять ключевые слова на страницу, которая отвечает на другой вопрос.

## Практика

### Перепишите заголовки для одного раздела

Возьмите пять страниц из одного раздела и перепишите их заголовки так, чтобы каждый начинался с отличительных слов. К каждому напишите описание, которое помогло бы ищущему решить.

Готово, когда: заголовки различимы между собой без названия сайта, и ни одно описание не повторяет просто свой заголовок.

### Добавьте структурированные данные и проверьте их

Разметьте одну статью с помощью JSON-LD, затем сверьте разметку с видимым содержимым страницы.

Готово, когда: каждое заявленное свойство видно на странице, а удаление видимого факта делает разметку неверной, а не просто устаревшей.

## Частые ошибки

- **Повтор названия сайта в каждом заголовке** — отличительные слова вытесняются из виду; исправить: ставьте предмет в начало.
- **Описание, повторяющее заголовок** — сниппет тратит единственный шанс описать страницу; исправить: суммируйте, на что отвечает страница.
- **Разметка данных, которых нет на странице** — поисковая система их игнорирует и может понизить сайт; исправить: размечайте только то, что может видеть посетитель.
- **«Нажмите здесь» как текст ссылки** — ни робот, ни скринридер не узнают назначение; исправить: опишите цель в тексте ссылки.
- **Выбор уровней заголовков по размеру шрифта** — план перестаёт описывать структуру содержимого; исправить: держите план логичным, а вид задавайте через CSS.
