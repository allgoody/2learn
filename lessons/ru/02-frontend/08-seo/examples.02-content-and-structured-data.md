## Пример 1 — Заголовок, описывающий сайт, а не страницу

Каждая страница сайта о ремонте несёт название сайта в качестве заголовка, у статьи два элемента `h1`, а её внутренние ссылки говорят, куда идти, только в окружающем предложении. Скажите, что теряет ищущий и что теряет робот, затем перепишите разметку.

```html
<title>Ремонт дома</title>
<h1>Ремонт дома</h1>
<h1>Починка протекающего радиатора</h1>
<p>Смотрите полное руководство. <a href="/guides/radiator">Читать далее</a></p>
```

### Решение

```html
<title>Починка протекающего радиатора — Ремонт дома</title>
<meta name="description" content="Разберитесь с протекающим радиатором, найдите отказавшее соединение и решите, стоит ли герметизировать его самостоятельно." />
<h1>Починка протекающего радиатора</h1>
<p>Смотрите <a href="/guides/radiator">как заново загерметизировать соединение радиатора</a>.</p>
```

Ищущий читает список результатов, и начало каждого заголовка — это то, что остаётся видимым, поэтому вынесение предмета вперёд и отличает эту страницу от других девяти с тем же названием сайта. Один `h1` на страницу говорит системе индексации, какая часть страницы является предметом, и это то же правило, которое применяет урок о доступности. Текст анкора — третий случай того же принципа: робот и пользователь скринридера узнают назначение ссылки из её слов, а «Читать далее» не говорит ни тому, ни другому. Описание ничего не повторяет и отвечает на то, для чего страница.

## Пример 2 — Структурированные данные, заявляющие рейтинг, которого страница не показывает

Разметка статьи утверждает агрегированный рейтинг, которого нет нигде на странице. Объясните, что делает это риском, а не оптимизацией, затем разметьте только то, что страница подтверждает.

```html
<script type="application/ld+json">
{
  "@context": "<адрес самого словаря>",
  "@type": "Article",
  "headline": "Починка протекающего радиатора",
  "aggregateRating": { "@type": "AggregateRating", "ratingValue": "4.9", "reviewCount": "312" }
}
</script>
```

### Решение

```html
<script type="application/ld+json">
{
  "@context": "<адрес самого словаря>",
  "@type": "Article",
  "headline": "Починка протекающего радиатора",
  "datePublished": "2026-02-14",
  "author": { "@type": "Person", "name": "А. Автор" }
}
</script>
```

Поисковые системы сверяют разметку с видимым содержимым, поэтому рейтинг, которого страница не показывает, считается нарушением и может стоить всех богатых результатов на сайте, а не только этого. Размечайте только свойства, которые видит посетитель: заголовок, дата публикации и автор есть на странице, и удаление одного из них наглядно сделало бы разметку неверной, а не просто устаревшей. Значение контекста называет словарь, из которого происходят типы, и записано здесь заглушкой, потому что этот корпус запрещает внешние ссылки; возьмите настоящее значение из документации этого словаря.
