## Пример 1 — Заголовок, описывающий сайт, а не страницу

На каждой странице сайта о ремонте заголовком служит название сайта, у статьи два элемента `h1`, а её внутренние ссылки говорят, куда идти, только в окружающем предложении. Скажите, что теряет ищущий и что теряет робот, затем перепишите разметку.

```html
<title>Ремонт дома</title>
<h1>Ремонт дома</h1>
<h1>Починка протекающего радиатора</h1>
<p>Смотрите полное руководство. <a href="/guides/radiator">Читать далее</a></p>
```

### Решение

```html
<title>Починка протекающего радиатора — Ремонт дома</title>
<meta name="description" content="Разберитесь с протекающим радиатором, найдите отказавшее соединение и решите, стоит ли герметизировать его самостоятельно." />
<h1>Починка протекающего радиатора</h1>
<p>Смотрите <a href="/guides/radiator">как заново загерметизировать соединение радиатора</a>.</p>
```

Один `h1` на страницу подсказывает системе индексации, какая именно часть страницы является предметом. Начало заголовка в списке результатов остаётся видимым — поэтому именно предмет, вынесенный вперёд, отличает эту страницу от других девяти с тем же названием сайта, тогда как описание не повторяет ничего и отвечает на то, для чего страница. И робот, и пользователь скринридера узнают назначение ссылки из её слов, однако «Читать далее» не говорит ни тому, ни другому: текст анкора — третий случай того же принципа.

## Пример 2 — Структурированные данные, заявляющие рейтинг, которого страница не показывает

В разметке статьи заявлен агрегированный рейтинг, которого на самой странице не показано нигде. Объясните, почему это риск, а не оптимизация; затем разметьте только то, что страница подтверждает.

```html
<script type="application/ld+json">
{
  "@context": "<адрес самого словаря>",
  "@type": "Article",
  "headline": "Починка протекающего радиатора",
  "aggregateRating": { "@type": "AggregateRating", "ratingValue": "4.9", "reviewCount": "312" }
}
</script>
```

### Решение

```html
<script type="application/ld+json">
{
  "@context": "<адрес самого словаря>",
  "@type": "Article",
  "headline": "Починка протекающего радиатора",
  "datePublished": "2026-02-14",
  "author": { "@type": "Person", "name": "А. Автор" }
}
</script>
```

Рейтинг, которого страница не показывает, поисковые системы считают нарушением: разметку они сверяют с видимым содержимым, и это может стоить всех богатых результатов на сайте, а не только этого. Размечайте только те свойства, которые видит посетитель: заголовок, дата публикации и автор есть на странице, и убери один из них — разметка станет не просто устаревшей, а неверной; значение контекста же называет словарь, из которого происходят типы, и записано здесь заглушкой, потому что этот корпус запрещает внешние ссылки, — настоящее значение возьмите из документации этого словаря.
