## Что это такое

Ajax — это техника обмена данными с сервером из уже работающей страницы, без полной перезагрузки. Изначально название расшифровывалось как Asynchronous JavaScript and XML; XML давно уступил место JSON, а сам механизм запроса перешёл от `XMLHttpRequest` к API `fetch`, но идея не изменилась: обновить часть страницы из сети, пока всё остальное остаётся на месте.

## Почему это важно

До Ajax каждое взаимодействие было отправкой формы и загрузкой страницы, то есть заметным мерцанием, потерянной позицией прокрутки и походом на сервер ради одной галочки. Ajax — это то, что заставляет приложение ощущаться приложением, а не документом, который перезагружается. Он же вводит класс проблем, которого нет у перезагружаемой страницы: частичное состояние. Страница может находиться посреди запроса, запрос может тихо отказать, а два запроса — обогнать друг друга, и поэтому понимать саму технику важнее, чем помнить имя API.

## Ключевые идеи

### Страница обновляется, а не заменяется

Запрос получает данные; затем код обновляет ту часть дерева, которая изменилась, и не трогает остальное. В этом вся выгода — ни повторного рендера шапки, ни потерянной позиции прокрутки — и в этом же источник сложности, потому что DOM и данные сервера теперь могут расходиться.

```js
async function refreshTotals() {
  const response = await fetch("/api/cart/totals");
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  const totals = await response.json();
  document.querySelector("[data-total]").textContent = formatMoney(totals.total);
}
```

### `fetch` завершается успешно, даже когда запрос не удался

Сетевой сбой отклоняет промис, но ответ 404 или 500 завершается успешно со `ok`, установленным в `false`. Считать любой успешно завершённый ответ успехом — самая частая ошибка в Ajax: HTML страницы с ошибкой разбирается как JSON, и сбой всплывает в виде сбивающей с толку ошибки разбора.

### Просите JSON и проверяйте форму

`response.json()` возвращает промис, потому что тело читается после прихода заголовков. Разобранное значение имеет тип `any`, поэтому ожидаемая форма остаётся предположением, пока что-нибудь её не проверит. Для всего, что сложнее прототипа, проверяйте на границе.

```js
const data = await response.json();
if (typeof data?.total !== "number") throw new Error("unexpected payload");
```

### Отправляйте данные правильным методом и типом

`POST` с телом JSON требует заголовка `Content-Type: application/json`; отправка формы должна использовать `FormData` без заголовка, чтобы границу задал браузер. Ошибка здесь даёт запрос, который сервер не может разобрать, и обычно это выглядит как пустое тело.

### Деградируйте, когда скрипт не запускается

Ссылка, которая выполняет переход, и форма, которая отправляется, — это запасной вариант для любого запроса, который скрипт не смог сделать. Построить разметку так, чтобы она работала без Ajax, и уже потом улучшать её — значит сохранить страницу рабочей, когда скрипт не загрузился или заблокирован.

## Практика

### Загрузите и отрисуйте список без перезагрузки

Сделайте кнопку, которая получает список, отрисовывает его на странице и показывает отдельное сообщение при сбое и пока запрос в полёте.

Готово, когда: кнопка показывает отключённое состояние загрузки, ответ 500 показывает сообщение об ошибке, а не пустой список, а остальная часть страницы не перерисовывается.

### Дайте форме рабочий запасной вариант

Возьмите форму, которая отправляется через Ajax, и убедитесь, что она работает с отключённым JavaScript, затем подтвердите, что улучшенный путь даёт тот же результат.

Готово, когда: путь без скрипта отправляется и отрисовывается корректно, а улучшенный путь обновляется на месте без перезагрузки.

## Частые ошибки

- **Предположение, что завершившийся `fetch` означает успех** — тело ответа 404 разбирается как ожидаемая полезная нагрузка; исправить: проверяйте `response.ok` и бросайте исключение со статусом.
- **Отрисовка до завершения запроса** — состояние загрузки сменяется пустым, и интерфейс выглядит сломанным; исправить: отрисовывайте три явных состояния: загрузка, готово и ошибка.
- **Два запроса, обгоняющих друг друга** — медленный ранний ответ перезаписывает быстрый поздний; исправить: прерывайте предыдущий запрос или игнорируйте ответ, чей запрос уже не актуален.
- **Забытый тип содержимого JSON при записи** — сервер получает неразбираемое тело; исправить: задайте `Content-Type: application/json` и сериализуйте через `JSON.stringify`.
- **Страница, которая работает только с Ajax** — заблокированный или упавший скрипт не оставляет ничего рабочего; исправить: начните с работающей ссылки или формы и улучшайте её.
