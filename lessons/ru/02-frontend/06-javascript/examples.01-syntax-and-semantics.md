## Пример 1 — Ноль, принятый за отсутствие

Объект настроек хранит число повторных попыток. Код ниже печатает одно и то же сообщение независимо от того, равно число нулю или отсутствует. Скажите, на какое правило здесь полагаются, затем сделайте намерение явным.

```js
const settings = { retries: 0, label: "" };

if (settings.retries) {
  console.log("будем повторять");
} else {
  console.log("попыток нет");   // выполняется, даже когда retries — настоящий 0
}

console.log(settings.label == false);   // true — обе стороны приведены
console.log([] == false);               // true — [] приводится к 0
```

### Решение

```js
if (settings.retries > 0) {
  console.log("будем повторять");
}

if (Object.hasOwn(settings, "retries")) {
  console.log("настройка задана");
}

console.log(settings.label === "");     // равенство без приведения
console.log([] === false);              // false
```

Ложных значений шесть — `false`, `0`, `""`, `null`, `undefined` и `NaN`, — поэтому проверка на истинность отвечает на вопрос «ложно ли это значение», а не «отсутствует ли оно», и законный `0` неотличим от отсутствующего ключа. Затем `==` приводит типы перед сравнением — поэтому пустой массив равен `false`. Запись `>` выражает числовое намерение, `Object.hasOwn` — намерение о наличии, а `===` прекращает приведение. Правила были там всегда; исходный код просто не говорил, на какой вопрос он отвечает.

## Пример 2 — Цикл, все колбэки которого видят последнее значение

Три функции собираются в цикле, и каждая должна вывести свой индекс. Все они выводят одно и то же число. Объясните, какую привязку они захватили, затем исправьте цикл, не меняя того, что он делает.

```js
const handlers = [];

for (var i = 0; i < 3; i++) {
  handlers.push(() => console.log(i));
}

handlers.forEach((handler) => handler());   // 3 3 3
```

### Решение

```js
const handlers = [];

for (let i = 0; i < 3; i++) {
  handlers.push(() => console.log(i));      // 0 1 2
}

handlers.forEach((handler) => handler());
```

Замыкание захватывает переменную, а не копию её значения, а `var` поднимается к объемлющей функции, поэтому все три стрелочные функции замыкаются на одну и ту же `i`, которая достигает 3 до того, как запустится любая из них. `let` блочный и создаёт свежую привязку на каждой итерации, поэтому каждый колбэк получает свою. То же правило объясняет, почему счётчик, построенный на замыкании, хранит своё приватное состояние между вызовами: функция помнит место, где была написана, а не то, где вызвана.
