## Что это такое

Модули делят JavaScript на файлы с явными импортами и экспортами, так что каждый файл может заявить, что ему нужно и что он предлагает. Инструменты — это то, что превращает эти файлы вместе с зависимостями и не-JavaScript-ресурсами во что-то, что браузер может эффективно загрузить. Их обычно изучают вместе, потому что именно модули делают инструменты осмысленными.

## Почему это важно

Один файл скрипта не масштабируется дальше нескольких сотен строк: каждое имя глобально, порядок загрузки решает корректность, и ничего нельзя переиспользовать без копирования. Модули дают коду границу и граф зависимостей — именно это вообще делает возможными тестирование, tree-shaking и ленивую загрузку. Инструменты существуют потому, что браузеры не умеют всего этого сами — по крайней мере, с теми же гарантиями, — и потому, что альтернатива, то есть доставка каждого файла и каждой зависимости каждому посетителю, — самая частая причина медленной первой загрузки.

## Ключевые идеи

### Именованные экспорты, явные импорты

ES-модуль объявляет, что он предлагает и что берёт. Именованные экспорты предпочтительнее экспорта по умолчанию: их переименовывают при импорте осознанно, они устойчивы к опечаткам и делают очевидным, чем является символ.

```js
// format.js
export function formatMoney(cents) { /* … */ }
export const CURRENCY = "GBP";

// invoice.js
import { formatMoney } from "./format.js";
```

Импорты поднимаются и являются живыми привязками — импортирующий модуль видит последующие изменения экспортированного `let`. Это отличается от скопированного значения и иногда удивляет.

### Модуль выполняется один раз

Выполнение модуля происходит один раз на URL, сколько бы мест его ни импортировало, а порядок определяется графом, а не тегами `<script>`. Поэтому операторы верхнего уровня в модуле выполняются при первом импорте; модуль, чей код верхнего уровня выполняет работу, — это модуль, который запускается в непредсказуемый момент.

### Динамический импорт разбивает граф

`import()` возвращает промис и загружает модуль по требованию. Так маршрут или тяжёлый редактор держатся вне начального бандла. Статический `import` этого не умеет: сборщик обязан включить цель в бандл точки входа.

```js
async function openEditor() {
  const { Editor } = await import("./editor.js");
  return new Editor();
}
```

### Сборщик существует, чтобы разрешать, преобразовывать и удалять

Сборщик разрешает спецификаторы модулей, преобразует синтаксис, который не поддерживают целевые браузеры, встраивает ресурсы и удаляет недостижимый код. Vite — распространённый современный выбор: в разработке он отдаёт нативные ES-модули, а для продакшна собирает бандл, что сохраняет цикл «правка — обновление» быстрым на больших проектах.

### Доставляйте меньше, измеряя

Инструменты без измерений растут. Смотрите, что в итоге попадает в собранный вывод, держите самые большие зависимости осознанными и предпочитайте возможности платформы библиотеке, когда платформа уже делает работу.

## Практика

### Разбейте скрипт на модули

Возьмите один файл с несколькими несвязанными функциями и разбейте его на три модуля с именованными экспортами, один из которых импортирует два других.

Готово, когда: ни у одного модуля нет больше одной причины меняться, а файл точки входа читается как короткий список импортов и один вызов.

### Лениво загрузите одну тяжёлую функцию

Найдите редко используемую, но крупную функцию — редактор форматированного текста, библиотеку графиков — и загружайте её динамическим `import()`, запускаемым тем взаимодействием, которому она нужна.

Готово, когда: панель сети показывает, что чанк не запрашивается при первой загрузке, а функция всё равно работает при первом вызове.

## Частые ошибки

- **Смешивание синтаксиса CommonJS и ES-модулей** — `require` падает в модуле, а `import` нельзя использовать условно; исправить: выбирайте ES-модули для нового кода и переводите границы осознанно.
- **Импорт ради побочного эффекта без пояснения** — зависимость невидима и может быть удалена как «неиспользуемая»; исправить: импортируйте используемую привязку или поясните комментарием, зачем нужен голый импорт.
- **Работа на верхнем уровне модуля** — она выполняется в непредсказуемый момент, и её нельзя ни отменить, ни повторить; исправить: экспортируйте функцию и вызывайте её из точки входа.
- **Добавление зависимости ради нескольких строк** — бандл растёт у всех, а цепочка поставок ширится; исправить: используйте API платформы или добавьте небольшую функцию к себе.
- **Отказ от осмотра продакшн-бандла** — фреймворк или файл локали удваивает передачу, и никто не замечает; исправить: проверяйте собранный вывод после добавления зависимости.
