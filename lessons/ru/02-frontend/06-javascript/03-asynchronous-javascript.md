## Что это такое

Асинхронный JavaScript — это то, как язык справляется с работой, которая завершается не сразу: сетевым запросом, таймером, чтением файла, — не замораживая страницу в ожидании. Вы запускаете работу, передаёте функцию, которая выполнится по её завершении, и браузер продолжает жить. Промисы и `async`/`await` — современные способы записать эту передачу.

## Почему это важно

Единственная блокирующая операция в главном потоке делает всю страницу неотзывчивой: вкладка перестаёт перерисовываться, клики копятся в очереди, и браузер в конце концов предлагает убить страницу. Поэтому каждое реалистичное приложение загружает, ждёт и повторяет, и почти каждая ошибка в таком приложении — ошибка порядка: работа, завершившаяся после того, как состояние, которое она должна была обновить, уже исчезло, либо два гонящихся запроса, либо ошибка, которую так и не поймали, потому что отклонению некуда было попасть. Асинхронная модель — не продвинутая тема; это форма кода, который выполняет браузер.

## Ключевые идеи

### Есть один поток и очередь

JavaScript выполняет по одной вещи за раз. Когда работа вроде сетевого вызова завершается, её колбэк ставится в очередь и запускается только после того, как текущий стек вызовов опустеет. Поэтому длинный цикл мешает сработать таймеру и поэтому код после `await` возобновляется позже, а не сразу.

```js
console.log("1");
setTimeout(() => console.log("3"), 0);
console.log("2");        // выводит 1, 2, 3
```

### Промис — это заполнитель с тремя состояниями

Промис находится в состоянии pending, затем либо fulfilled со значением, либо rejected с причиной — один раз и больше никогда. `.then` и `.catch` присоединяют колбэки; возвращаемое значение `.then` — это ещё один промис, чем и работает цепочка.

```js
fetch("/api/orders")
  .then((response) => {
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    return response.json();
  })
  .then((orders) => render(orders))
  .catch((error) => showError(error));
```

Обратите внимание на проверку: `fetch` переходит в fulfilled и для 404, и для 200. Сетевой сбой отклоняет промис; статус ошибки — нет.

### `async`/`await` — то же самое, но записанное линейно

`async`-функция всегда возвращает промис, а `await` приостанавливает её, пока ожидаемый промис не завершится, и продолжает со значением или выбрасывает причину. Оборачивайте в `try`/`catch`; необработанное отклонение во многих контекстах проходит молча.

```js
async function loadOrders() {
  try {
    const response = await fetch("/api/orders");
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    return await response.json();
  } catch (error) {
    showError(error);
    return [];
  }
}
```

### Независимая работа должна идти параллельно

Ожидание по очереди ждёт суммы длительностей; `Promise.all` ждёт самую долгую из них. `Promise.allSettled` отдаёт все результаты, включая неудачные, — обычно это и нужно, когда один сбой не должен отменять остальные.

```js
const [user, orders] = await Promise.all([loadUser(id), loadOrders(id)]);
```

### Отмена и устаревание — ваша забота

Промис нельзя отменить, но лежащий под ним запрос можно, с помощью `AbortController`. Когда пользователь набирает новый запрос, отмените предыдущий или проигнорируйте его результат — иначе победит самый медленный ответ.

### Никогда не оставляйте отклонение необработанным

Каждой цепочке промисов нужен `catch`, а каждому `await` — окружающий `try`. В браузере необработанное отклонение доходит до события `unhandledrejection`; в Node оно может завершить процесс.

## Практика

### Загрузите три эндпоинта одновременно

Загрузите три независимых ресурса и отрисуйте их вместе — сначала последовательно, затем через `Promise.all`, замерив оба варианта.

Готово, когда: параллельный вариант занимает примерно столько же, сколько самый медленный запрос, а не их сумма, и неудачный запрос по-прежнему показывает ошибку, а не пустую страницу.

### Отмените устаревший поиск

Постройте поле поиска, которое запускает запрос на каждое нажатие клавиши. Отменяйте предыдущий запрос через `AbortController`, когда начинается новый.

Готово, когда: быстрый набор никогда не отрисовывает результаты для более раннего запроса, а панель сети показывает брошенные запросы как отменённые.

## Частые ошибки

- **Забыть, что `fetch` переходит в fulfilled при статусе ошибки** — ответ 500 считается успехом, и разбор JSON падает непонятно; исправить: проверяйте `response.ok` и выбрасывайте ошибку.
- **Ожидание независимых запросов по очереди** — страница ждёт сумму длительностей; исправить: запускайте их вместе и ожидайте `Promise.all`.
- **Оставленный промис без `catch`** — отклонение исчезает, а интерфейс остаётся в состоянии загрузки; исправить: присоединяйте обработчик к каждой цепочке и оборачивайте каждый `await`.
- **Чтение состояния после `await` в предположении, что оно не изменилось** — значение могло быть заменено, пока запрос был в полёте; исправить: захватите нужное до ожидания или защититесь отменой.
- **Использование `await` внутри обычного `forEach`** — колбэки не ожидаются, и цикл завершается первым; исправить: используйте `for...of` или `Promise.all` поверх `map`.
