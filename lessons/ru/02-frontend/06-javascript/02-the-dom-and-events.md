## Что это такое

DOM — это живая объектная модель документа в браузере: по одному узлу на элемент, атрибут и фрагмент текста, доступная из JavaScript и изменяемая на месте. События — это сообщения, которые браузер посылает, когда что-то происходит: клик, нажатие клавиши, ответ сети, — и DOM — то место, где на них подписываются.

## Почему это важно

Здесь страница перестаёт быть документом и становится приложением. Каждое интерактивное поведение, от выпадающего списка до живого поиска, — это работа с DOM плюс обработка событий. Здесь же живут две самые частые проблемы производительности и корректности: слушатели, продолжающие работать после исчезновения элемента, и обработчики, обновляющие DOM так, что браузер пересчитывает раскладку снова и снова. Понимание API — и его цены — отличает код, отвечающий мгновенно, от кода, который заикается.

## Ключевые идеи

### Сначала запросите дерево, потом меняйте его

`querySelector` и `querySelectorAll` принимают CSS-селекторы, поэтому знание селекторов из CSS применимо напрямую. Меняйте элементы, задавая свойства (`textContent`, `classList`, `value`), а не переписывая HTML-строки; `innerHTML` разбирает и пересобирает всё заново, что медленнее и служит путём для внедрённой разметки.

```js
const list = document.querySelector("#results");
list.textContent = "";
```

Осторожно с `querySelectorAll`: он возвращает статический `NodeList`, а не живой, — обходите его через `for...of` или `Array.from`, а не методами массива.

### Стройте узлы вместо склейки строк

`document.createElement` и `append` дают настоящий узел, свойства которого можно задавать, а браузер пересчитывает раскладку один раз при вставке. Сборка строки и её присваивание разбирают всё заново и выбрасывают старое поддерево.

```js
const item = document.createElement("li");
item.textContent = row.name;
list.append(item);
```

### События всплывают, и это возможность

Событие срабатывает на своей цели и затем идёт вверх по предкам. Слушатель на контейнере, проверяющий `event.target`, — делегирование — позволяет одному слушателю покрыть все строки, включая добавленные позже. Это стандартное лекарство сразу от двух проблем: «мой слушатель пропал» и «у меня двести слушателей».

```js
list.addEventListener("click", (event) => {
  const button = event.target.closest("button[data-id]");
  if (!button) return;
  removeRow(button.dataset.id);
});
```

### Предотвращайте стандартное поведение, только когда это осознанно

`event.preventDefault()` останавливает собственное поведение браузера — переход по ссылке, отправку формы. Вызов его на каждом клике, чтобы «страница не прыгала», ломает средний клик, активацию с клавиатуры и валидацию формы. `stopPropagation` нужен для вложенных интерактивных областей и должен встречаться редко.

### Убирайте то, что навесили

Слушатель держит свой элемент и своё замыкание живыми, пока элемент прикреплён. Когда вы удаляете элемент, его слушатели уходят вместе с ним; когда вы навешиваете на `window` или `document` — нет. Снимайте всё долгоживущее.

## Практика

### Отрисуйте список через делегирование

Постройте список элементов с кнопкой удаления в каждой строке, добавляемых из массива данных, с единственным слушателем клика на контейнере.

Готово, когда: клик по кнопке любой строки удаляет эту строку, а добавление строки после загрузки страницы работает без нового слушателя.

### Посмотрите на reflow в панели производительности

Напишите цикл, который читает `offsetHeight` и затем пишет стиль на каждой итерации. Запишите профиль, затем перестройте цикл так, чтобы сначала всё прочитать, а потом всё записать, и запишите снова.

Готово, когда: вторая запись показывает сгруппированную работу раскладки, а не повторяемую на каждой итерации.

## Частые ошибки

- **Вызов `querySelectorAll` и последующее использование методов массива** — у `NodeList` нет `map`, и код падает; исправить: преобразуйте через `Array.from` или обходите через `for...of`.
- **Навешивание слушателя внутри цикла по тем же элементам** — работа растёт вместе со списком, а дублирующиеся обработчики срабатывают вместе; исправить: навесьте один делегированный слушатель на контейнер.
- **Чтение свойств раскладки после каждой записи** — каждое чтение заставляет браузер пересчитывать раскладку, и цикл заикается; исправить: группируйте чтения, затем записи.
- **Использование `innerHTML` с пользовательским содержимым** — строка разбирается как разметка, и недоверенный текст становится элементом; исправить: задавайте `textContent` или стройте узлы.
- **Забыть, что `event` исчезает после возврата обработчика** — он переиспользуется, а его свойства очищаются; исправить: читайте нужное в переменную прямо во время работы обработчика.
