## Что это такое

Sass — это язык таблиц стилей, который компилируется в CSS. Он добавляет переменные, вложенность, партиалы, миксины и функции к обычному каскаду, так что большую таблицу стилей можно разбить по файлам, а повторяющийся блок правил написать один раз. SCSS — его основной синтаксис, остающийся надмножеством CSS: любая валидная таблица стилей является валидным файлом SCSS.

## Почему это важно

Много лет Sass был тем, как команда выживала с таблицей стилей длиннее нескольких сотен строк, и изрядная доля продакшен-CSS до сих пор собирается так. Многие его возможности с тех пор поглотил сам CSS — пользовательские свойства, нативная вложенность, `color-mix()`, — и это меняет то, для чего кодовая база на Sass всё ещё должна его использовать. Понимание того, какие части стали избыточными, не даёт тащить шаг сборки без причины, а понимание того, какие не стали, держит большую существующую кодовую базу сопровождаемой.

## Ключевые идеи

### Партиалы и `@use` организуют, не протекая наружу

Партиал — это файл, чьё имя начинается с подчёркивания; `@use` загружает его один раз, под пространством имён, и его члены видны там, где нужны. `@use` заменил более старый `@import`, который загружал один и тот же файл повторно и помещал каждую переменную в общую глобальную область видимости.

```scss
// _scale.scss
$step: 0.25rem;

@function spacing($n) {
  @return $step * $n;
}

// card.scss
@use "scale";

.card { padding: scale.spacing(4); }
```

### Миксины — для блоков правил, функции — для значений

Миксин испускает объявления и может принимать аргументы; функция возвращает значение. Повторение градиента или стиля фокуса — это миксин; вычисление шага отступа или контрастно-безопасного цвета — это функция. Сохранение этого различия делает место вызова очевидным насчёт того, что ему нужно.

```scss
@mixin focus-ring($color: currentColor) {
  outline: 3px solid $color;
  outline-offset: 2px;
}

.button:focus-visible { @include focus-ring(teal); }
```

### Вкладывайте сдержанно

Вложенность Sass — это удобство, а не разрешение: каждый уровень повышает специфичность скомпилированного селектора, а глубокая вложенность порождает селекторы, которые нельзя переопределить без ещё одного уровня. Вложить один уровень и использовать `&` для состояния или модификатора — устойчивый предел.

```scss
.card {
  padding: 1rem;

  &.is-selected { border-color: teal; }
}
```

### Знайте, что CSS теперь делает бесплатно

Пользовательские свойства заменили большинство случаев применения переменных, потому что это значения времени выполнения, изменяемые для поддерева. Нативная вложенность заменила структурную. `clamp()`, `min()`, `max()` и `color-mix()` заменили многие функции. По-настоящему уникально полезной остаётся машинка времени компиляции: циклы по карте, порождающие систематический набор утилит, и функции, дающие значения, которые CSS вычислить не может.

```scss
$sizes: (sm: 0.75rem, md: 1rem, lg: 1.5rem);

@each $name, $size in $sizes {
  .button--#{$name} { font-size: $size; }
}
```

### Порядок компиляции и размер вывода — реальные заботы

Sass может породить большой объём CSS из малого объёма исходника: цикл по карте цветов и размеров краток в написании и дорог в доставке. Проверяйте скомпилированный вывод и предпочитайте сборку, испускающую только то, что использует страница.

## Практика

### Замените переменную Sass пользовательским свойством

Возьмите переменную Sass, использованную для фирменного цвета, и перенесите её в пользовательское свойство CSS. Измените её для одного поддерева без повторной компиляции.

Готово, когда: цвет можно поменять во время выполнения, задав свойство на контейнере, и ни одна переменная Sass больше не дублирует значение.

### Сгенерируйте набор утилит из карты

Напишите цикл Sass, порождающий модификаторы размера кнопки из карты из трёх шагов, затем сравните размер скомпилированного вывода с тремя написанными вручную правилами.

Готово, когда: цикл порождает те же правила, что и рукописная версия, и вы можете объяснить, когда меньший исходник цикла оправдывает больший вывод.

## Частые ошибки

- **Глубокая вложенность в угоду разметке** — скомпилированные селекторы набирают специфичность и становятся непереопределяемыми; исправить: вкладывайте один уровень и используйте `&` для состояний.
- **Переменная Sass там, где подходит пользовательское свойство** — значение фиксируется во время сборки и не поддаётся темизации; исправить: используйте пользовательское свойство для всего, что меняется во время выполнения.
- **Подключение партиала, испускающего правила, в нескольких местах** — одни и те же объявления дублируются в выводе; исправить: используйте `@use` и подключайте партиалы с правилами один раз.
- **Генерация всех комбинаций в таблицу стилей** — цикл по цветам и размерам может утроить объём CSS; исправить: проверяйте размер компиляции и генерируйте только используемое.
- **Таскание Sass ради возможностей, которые уже есть в CSS** — шаг сборки остаётся без выгоды; исправить: проведите ревизию файла и уберите то, что нативная вложенность и пользовательские свойства уже покрывают.
