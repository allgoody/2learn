## Пример 1 — Вложенность, повторяющая разметку

Вложенность ниже повторяет DOM на четыре уровня вглубь. Небольшое изменение дизайна требует ещё одного уровня для переопределения. Скажите, что каждый уровень делает со скомпилированным селектором, затем выровняйте вложенность до устойчивого предела.

```scss
.card {
  .card__header {
    .card__title {
      .card__badge {
        color: teal;
      }
    }
  }
}
```

### Решение

```scss
.card {
  padding: 1rem;

  &.is-selected { border-color: teal; }
}

.card__title { font-size: 1.125rem; }
.card__badge { color: teal; }
```

Вложенность Sass — удобство для автора, а не область видимости: каждый уровень конкатенируется в скомпилированный селектор, поэтому четыре уровня дают селектор со специфичностью четырёх классов, которую следующему разработчику придётся перебивать пятью. Вложенность в один уровень с `&` для состояния или модификатора держит скомпилированный вывод плоским и переопределяемым и не даёт форме таблицы стилей зависеть от формы разметки. Имена классов уже говорят, какому элементу они принадлежат, поэтому вложенность не добавляла информации — только специфичность. Та же сдержанность применима и к нативной вложенности CSS.

## Пример 2 — Переменная Sass там, где значение должно меняться во время выполнения

Фирменный цвет — это переменная Sass, поэтому второй бренд требует второй таблицы стилей. Скажите, почему переменная не справляется с этой задачей, затем перенесите значение в пользовательское свойство.

```scss
$brand: #0f766e;

.button {
  background: $brand;
  border-color: $brand;
}

// чтобы перетемизировать раздел, требовалась целая вторая компиляция
```

### Решение

```scss
:root { --brand: #0f766e; }

.button {
  background: var(--brand);
  border-color: var(--brand);
}

.brand-partner { --brand: #1d4ed8; }
```

Переменная Sass подставляется во время сборки, поэтому значение закрепляется в скомпилированном CSS и каждая вариация требует отдельной сборки; пользовательское свойство — это значение времени выполнения, которое наследуется, поэтому задание его на обёртке перетемизирует всё внутри без второй компиляции и без селектора на каждый компонент. Это та часть Sass, которую нативный CSS сделал избыточной, и ради неё стоит провести ревизию файла: переменные, использованные для всего, что меняется во время выполнения, должны стать пользовательскими свойствами, а Sass сохраняет работу, которую CSS всё ещё не может делать, — циклы по карте, порождающие систематический набор правил, и функции, вычисляющие значения. Оставьте шаг сборки только ради того, что он действительно несёт.
