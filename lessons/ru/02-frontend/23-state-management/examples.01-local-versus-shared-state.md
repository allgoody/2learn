## Пример 1 — Два компонента, синхронизирующие один факт

Поле поиска и счётчик результатов держат каждый свою копию запроса, синхронизируя их эффектом. Быстрое двойное нажатие оставляет их с разными значениями. Скажите, что скрывает эффект, затем дайте значению одного владельца.

```jsx
function SearchField() {
  const [query, setQuery] = useState("");
  return <input value={query} onChange={(e) => setQuery(e.target.value)} />;
}

function ResultCount({ results }) {
  const [query, setQuery] = useState("");
  const [count, setCount] = useState(0);

  useEffect(() => {
    setCount(results.filter((r) => r.name.includes(query)).length);
  }, [results, query]);
  return <span>{count} shown</span>;
}
```

### Решение

```jsx
function Page({ results }) {
  const [query, setQuery] = useState("");
  const count = results.filter((r) => r.name.includes(query)).length;

  return (
    <>
      <SearchField value={query} onChange={setQuery} />
      <ResultCount count={count} />
    </>
  );
}
```

Две копии одного факта расходятся, а эффект, поддерживающий их синхронность, выполняется после рендера, а не во время него, поэтому взаимодействие, меняющее оба значения в одном такте, может оставить их в разногласии — из-за этого баг и выглядит как проблема отрисовки. Подъём — это перенос владельца, а не добавление синхронизатора: значение уходит к ближайшему общему предку, который передаёт вниз значение и наверх сеттер, а локальные копии удаляются. Счётчик после этого выводится во время рендера, а не хранится, поэтому устареть он не может вовсе.

## Пример 2 — Запись хранилища, которую читает только один экран

Хранилище держит выбранную строку одной таблицы вместе с эффектом, который сбрасывает её при размонтировании экрана. Больше никто это значение не читает. Скажите, чего стоит хранилище, затем верните значение туда, где его используют.

```js
// store.js
export const useAppStore = create((set) => ({
  selectedRow: null,
  setSelectedRow: (id) => set({ selectedRow: id }),
  resetSelection: () => set({ selectedRow: null }),
}));

// OrdersTable.jsx
useEffect(() => () => resetSelection(), []);   // очистка для локального значения
```

### Решение

```jsx
function OrdersTable() {
  const [selectedRow, setSelectedRow] = useState(null);
  // сбрасывать нечего: размонтирование забирает значение с собой
  return <table>{/* строки вызывают setSelectedRow(row.id) */}</table>;
}
```

Глобальное хранилище живёт дольше экрана, поэтому значение, принадлежащее одному экрану, приходится чистить вручную — и эта очистка и есть признак того, что значение никогда не было общим. Локальное хранение означает, что сбрасывать нечего, сериализовать нечего и нет записи, которую следующий экран может случайно прочитать; время жизни компонента — это время жизни значения. Направление движения — от локального наружу: поднимайте значение только тогда, когда появился второй, далёкий читатель или когда оно должно пережить навигацию. Хранилище заслуживает место сквозной задачей, а не важностью.
