## Пример 1 — Три флага, которые могут быть истинными одновременно

Экран со списком отслеживает загрузку, ошибку и данные по отдельности. При медленной повторной попытке экран на миг показывает спиннер, ошибку и предыдущие строки одновременно. Скажите, что допускает тип, затем смоделируйте запрос одним значением.

```ts
let loading = false;
let error: Error | null = null;
let data: Item[] = [];

// во время неудачного обновления: loading true, ошибка задана, data всё ещё заполнена
```

### Решение

```ts
type Query<T> =
  | { status: "idle" }
  | { status: "loading" }
  | { status: "error"; error: Error }
  | { status: "ready"; data: T; stale: boolean };

function render(query: Query<Item[]>) {
  switch (query.status) {
    case "ready": return listItems(query.data, query.stale);
    case "error": return showError(query.error);
    case "loading": return spinner();
    case "idle": return null;
  }
}
```

Три независимые переменные описывают восемь комбинаций, и несколько из них бессмысленны — «загружается, содержит ошибку и держит данные» — не состояние, в котором может находиться запрос, и именно это дают флаги, когда расходятся. Размеченное объединение хранит один факт, поэтому невозможные комбинации нельзя записать, а рендерер не может прочитать `data` вне ветви, где она существует. Флаг `stale` в состоянии ready — та деталь, которую стоит заметить: фоновое обновление не возвращает в loading, поэтому предыдущее значение остаётся видимым, и интерфейс говорит, что обновляется, а не пустеет до спиннера.

## Пример 2 — Инвалидация перезагрузкой всего

Действие удаления повторно запрашивает каждый список на экране, поэтому страница мерцает, а четыре запроса возвращают неизменившиеся данные. Скажите, что было нужно кэшу вместо этого, затем обновите затронутую запись.

```ts
async function deleteOrder(id: string) {
  await fetch(`/api/orders/${id}`, { method: "DELETE" });
  await refetchOrders();
  await refetchCustomers();
  await refetchDashboard();
}
```

### Решение

```ts
async function deleteOrder(id: string) {
  const response = await fetch(`/api/orders/${id}`, { method: "DELETE" });
  if (!response.ok) throw new Error(`HTTP ${response.status}`);

  cache.remove("orders:page=1", (order) => order.id === id);
  cache.markStale("dashboard:summary");     // обновляется в фоне
}
```

Серверные данные — кэш, а не источник правды, поэтому вопрос после записи не «перезагрузить», а «какие записи кэша затронула эта запись» — и назвать эти ключи и есть вся работа. Удаление строки из списка, которому она принадлежала, делает изменение мгновенно видимым без сетевого обхода, а пометка производной сводки устаревшей позволяет ей обновиться за предыдущим значением, а не стереть его. Ключ каждой записи по её входным данным — то, что вообще делает точную инвалидацию возможной; кэш без ключей и без срока годности — баг с длинным запалом.
