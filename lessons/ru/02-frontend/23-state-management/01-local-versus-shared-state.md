## Что это такое

Локальное состояние принадлежит одному компоненту, и больше никто его не читает: открыто ли меню, что набрано в поле, какая строка выбрана в одной таблице. Общее состояние читают несколько частей интерфейса, поэтому ему нужны владелец, путь обновления и имя.

## Почему это важно

Самое дешёвое состояние — то, которого больше никто не видит, потому что оно не может устареть в другом месте. Каждое значение, поднятое в глобальное хранилище, потеряло свою локальность: теперь ему нужны имя, правило сброса, место в начальном состоянии и ответ на вопрос «что происходит при навигации». Приложения, которые рано складывают всё в одно хранилище, получают хранилище, повторяющее дерево компонентов, и большой объём кода, единственная задача которого — синхронизировать два представления одного экрана. Обратный отказ тоже настоящий — протаскивание значения через шесть компонентов, которые им не пользуются, — поэтому правило задаёт направление движения, а не фиксированный ответ.

## Ключевые идеи

### Начинайте локально и поднимайте только при необходимости

Значение сначала живёт в компоненте, который его отображает. Когда его нужно прочитать второму компоненту, поднимите его к ближайшему общему предку и передайте вниз. Только когда этот путь становится обузой — потому что значение нужно в далёких ветвях или между маршрутами, — хранилище стоит заводить.

```js
// Локально: больше никто не может его увидеть или инвалидировать
const [open, setOpen] = useState(false);
```

Триггер для подъёма — второй читатель, а не ощущение, что значение «важное».

### Подъём состояния — это перенос владельца, а не копирование

Подъём — не то же самое, что зеркалирование. Если два компонента держат по копии и синхронизируют их эффектами, копии разойдутся — обычно сразу после быстрого взаимодействия. Перенесите значение к родителю, передайте вниз значение и сеттер как проп, а локальные копии удалите.

```jsx
function Page() {
  const [query, setQuery] = useState("");
  return (
    <>
      <SearchField value={query} onChange={setQuery} />
      <ResultCount query={query} />
    </>
  );
}
```

### Хранилище заслуживает место, когда оно сквозное

Хранилища хороши для значений, которые читают и пишут многие далёкие части приложения, которые должны пережить навигацию или должны сериализоваться, — текущий пользователь, тема, несохранённый черновик. Они плохи для значений, описывающих один экран, потому что хранилище живёт дольше экрана, и его записи приходится чистить вручную.

### Разным задачам подходят разные формы

Единое хранилище с действиями и редьюсерами делает каждое изменение отслеживаемым, что подходит приложениям со сложным состоянием, которое нужно аудировать. Маленькое хранилище с прямыми сеттерами легче для простых случаев. Реактивные примитивы — сигналы — позволяют фреймворку отслеживать зависимости через обычные значения и вовсе обойтись без хранилища. Названия различаются; компромисс между отслеживаемостью, церемонией и связанностью — нет.

### Держите правило обновления в одном месте

Где бы значение ни жило, запишите, кому его можно менять. Значение, которое три компонента меняют напрямую, невозможно осмыслить, а его баги требуют чтения всех трёх. Одна функция обновления, даже тривиальная, даёт изменению одно место для проверки и одно место для журналирования.

## Практика

### Верните значение обратно в локальное состояние

Найдите в глобальном хранилище значение, которое читает только один экран. Перенесите его в локальное состояние этого экрана и удалите из хранилища, включая правила сброса при размонтировании.

Готово, когда: экран ведёт себя так же, хранилище больше не упоминает это значение, и одним путём очистки стало меньше.

### Поднимите значение к ближайшему общему владельцу

Найдите два компонента, каждый из которых держит копию одного факта и синхронизирует их эффектом. Удалите обе копии, поднимите значение к их общему родителю и передайте вниз вместе с сеттером.

Готово, когда: для синхронизации не осталось ни одного эффекта, и оба компонента обновляются вместе при каждом изменении, включая быстрый двойной клик.

## Частые ошибки

- **Складывание всего в одно глобальное хранилище** — хранилище повторяет дерево компонентов и требует ручной очистки при каждой навигации; исправить: держите значение локальным, пока не появится второй читатель.
- **Зеркалирование вместо подъёма** — две копии расходятся, и баг выглядит как проблема отрисовки; исправить: один владелец, переданный вниз.
- **Вывод состояния в эффекте** — лишний рендер и второй источник правды, который может разойтись; исправить: вычисляйте производные значения во время рендера.
- **Забытый сброс состояния хранилища при уходе с экрана** — следующий визит показывает данные прошлого; исправить: ограничьте хранилище экраном или сбрасывайте его явно при входе и выходе.
- **Прямая запись одного значения многими компонентами** — изменением не управляет одно правило, и каждый баг требует прочитать три файла; исправить: направляйте записи через одну функцию обновления.
