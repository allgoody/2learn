## Пример 1 — Вложенные flex-контейнеры вместо двух измерений

Каркасу страницы нужны фиксированная боковая панель и плавная основная колонка. Он построен из flex-контейнеров, и потребовался третий уровень, чтобы разместить панель инструментов рядом с таблицей. Скажите, почему вложенность всё растёт, затем замените внешнюю структуру.

```html
<div class="layout">
  <aside class="side">Фильтры</aside>
  <main class="content">
    <div class="toolbar">Панель инструментов</div>
    <div class="table">Строки</div>
  </main>
</div>
```

```css
.layout { display: flex; }
.side { width: 16rem; }
.content { display: flex; flex-direction: column; }
```

### Решение

```css
.layout { display: grid; grid-template-columns: 16rem 1fr; gap: 1.5rem; }
.content { display: flex; flex-direction: column; gap: 1rem; }
```

Flexbox распределяет элементы вдоль одной оси, поэтому двумерная структура, собранная из него, требует контейнера на каждую ось, и вложенность растёт с каждой новой областью. Grid сначала задаёт дорожки и размещает элементы по ним — это одно объявление на весь каркас. Вычисленный результат на окне 1200px: боковая панель ровно 256px, gap 24px, а колонка содержимого забирает оставшиеся 920px. Вложенные flex-контейнеры внутри ячейки grid нормальны и ожидаемы — запах в глубине внешней структуры, где справился бы один grid.

## Пример 2 — Flex-элемент, который не желает сжиматься

Метка и кнопка копирования стоят в одной строке. Когда метка держит длинный неразрывный токен, строка переполняется, и кнопку выталкивает из вида. Объясните умолчание, которое это вызывает, затем разрешите элементу сжиматься.

```html
<div class="row">
  <span class="label">averylongunbrokentokenthatcannotwrap</span>
  <button>Копировать</button>
</div>
```

```css
.row { display: flex; gap: 0.5rem; }
.label { flex: 1; }
/* строка шире своего контейнера, и кнопка исчезает */
```

### Решение

```css
.row { display: flex; gap: 0.5rem; }
.label { flex: 1; min-width: 0; overflow-wrap: anywhere; }
```

Автоматический минимальный размер flex-элемента равен ширине его содержимого в самом узком виде, поэтому `flex: 1` не может сжать метку ниже ширины этого единственного неразрывного токена — элемент вырастает сверх своей доли и тянет за собой всю строку. `min-width: 0` убирает этот пол, а `overflow-wrap: anywhere` даёт браузеру место для переноса. Вычисленный результат в строке 300px: кнопка остаётся примерно 72px, gap 8px, метка 220px, а токен переносится на две строки вместо переполнения. Поля и отрицательные смещения тут не помогут, потому что ограничение — это правило размеров, а не выравнивания.
