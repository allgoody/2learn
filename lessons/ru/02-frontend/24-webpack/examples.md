## Пример 1 — Целая библиотека, импортированная ради одной функции

Нужен один строковый помощник, и файл точки входа импортирует экспорт пакета по умолчанию. Бандл вырос на два порядка. Скажите, как сборщик решил, что включить, затем импортируйте только используемое.

```js
// src/index.js
import _ from "lodash";

const slug = _.kebabCase(title);
```

```text
пример вывода
main.[contenthash].js   72 kB
```

### Решение

```js
// src/index.js
import kebabCase from "lodash/kebabCase";

const slug = kebabCase(title);
```

```text
пример вывода
main.[contenthash].js   3.1 kB
```

Сборщик не загружает перечисленные вами файлы — он их находит, начиная с точки входа и следуя каждому импорту, поэтому импорт по умолчанию втягивает точку входа этого пакета и всё, до чего она дотягивается. Импорт конкретного модуля оставляет остальную часть графа вне бандла, а там, где у пакета вовсе нет маленькой точки входа, честный ответ — зависимость поменьше или несколько строк, написанных вручную. Поскольку граф обнаруживается, а не объявляется, случайный импорт в любом месте меняет вывод — поэтому осмотр бандла после добавления зависимости часть работы, а не необязательный аудит.

## Пример 2 — Отладочная сборка, отправленная в продакшн

Одна и та же конфигурация обслуживает локальную работу и развёрнутый сайт, а на выходе — один нехешированный файл с читаемыми именами функций. Скажите, чего стоит каждая отсутствующая настройка, затем разделите две сборки.

```js
export default {
  entry: "./src/index.js",
  output: { filename: "bundle.js" },
};
```

### Решение

```js
export default {
  mode: "production",
  entry: "./src/index.js",
  output: { filename: "[name].[contenthash].js", clean: true },
};
```

`mode` переключает весь набор значений по умолчанию, и без него сборка остаётся в отладочной форме: не минифицированная, без tree shaking и с удобным для отладки кодом, который стоит байтов и времени разбора каждому посетителю. Хеш содержимого в имени файла — вторая половина: он меняется только при изменении содержимого файла, и именно это позволяет браузеру кэшировать бандл надолго вместо повторной загрузки при каждом развёртывании. `clean` удаляет из выходного каталога устаревшие артефакты, чтобы старый хешированный файл нельзя было отдать по ошибке. Разработка и продакшн хотят противоположного — быстрых пересборок и читаемого исходного кода против маленького, хешированного, прошедшего tree shaking вывода, — и большая часть сложности конфигурации идёт из попытки обслужить обе задачи одним объектом настроек.
