## Что это такое

Система типов TypeScript позволяет описать форму значения — какие у него свойства, что в них лежит, что функция принимает и возвращает. Компилятор сравнивает эти описания и сообщает, где они расходятся. Система структурная: два типа совместимы, если у них одни и те же члены, независимо от названий.

## Почему это важно

Ценность системы типов пропорциональна тому, сколько она способна вывести без подсказок. Кодовая база, полная написанных вручную аннотаций, — это вторая, поддерживаемая руками копия программы, и она со временем расходится с оригиналом. Кодовая база, где большинство типов выведено, — это набор небольших объявлений на границах: параметры функций, экспортируемые формы, — а всё внутри проверяется от них. Умение видеть, где проходят эти границы, и есть весь навык; оно же отличает TypeScript как полезный инструмент от TypeScript как дополнительной работы без выгоды.

## Ключевые идеи

### Типы структурные, а не номинальные

Объект совместим с типом, если у него есть все требуемые члены совместимых типов. Не нужно объявлять, что класс реализует интерфейс, чтобы значение этого класса ему удовлетворяло. Два независимо объявленных типа с одинаковой формой взаимозаменяемы.

```ts
type Point = { x: number; y: number };

const origin = { x: 0, y: 0, label: "O" };
const p: Point = origin;   // нормально — лишние свойства здесь допустимы
```

Исключение — проверка лишних свойств: присваивание объектного литерала прямо типизированной переменной действительно отмечает неизвестные свойства, именно потому, что опечатка обычно случается там.

### Пусть вывод делает работу

Аннотируйте параметры, когда их нельзя вывести, и возвращаемые типы экспортируемых функций, чтобы у вызывающего кода был устойчивый контракт. Внутри функции позвольте компилятору самому определить тип локальной переменной: неверная аннотация там — это ошибка, а не документация.

```ts
function totalCents(items: CartItem[]): number {
  return items.reduce((sum, item) => sum + item.priceCents * item.quantity, 0);
}
```

### Для объединений берите `type`, для расширения — `interface`

Оба описывают форму объекта. `interface` можно открыть заново и слить с другим объявлением — это полезно для дополнения библиотек и опасно во всех остальных случаях. `type` составляет объединения и пересечения и слиянию не поддаётся, что делает его более безопасным выбором по умолчанию для прикладного кода.

### Моделируйте отсутствие явно

`strict: true` делает `null` и `undefined` обычными типами, а не чем-то, что прячется за каждым значением. Один этот флаг превращает «cannot read property of undefined» из падения во время выполнения в ошибку компиляции, и его стоит включать первым.

```ts
type User = { id: string; name: string; deletedAt: string | null };
```

### `any` отключает проверку для значения

`any` заразен для всего, чего касается. `unknown` — безопасный аналог: он принимает что угодно, но требует проверки перед использованием. Там, где границу действительно нельзя типизировать — сторонний скрипт, полезная нагрузка JSON, — предпочитайте `unknown` плюс функцию сужения на краю.

## Практика

### Типизируйте границу, остальное выводите

Возьмите небольшой модуль на JavaScript, который получает данные и отрисовывает их. Аннотируйте только возвращаемый тип функции загрузки и параметр функции отрисовки, затем запустите компилятор с включённым `strict` и исправьте то, что он сообщит, не добавляя аннотаций больше нигде.

Готово, когда: модуль компилируется со `strict`, ни одна локальная переменная не несёт явной аннотации, и компилятор ловит намеренную опечатку, которую вы вносите в отрисовку.

### Замените три `any` настоящим типом

Найдите три употребления `any` в кодовой базе, выпишите форму, которая на самом деле есть у каждого значения, и замените их типом или `unknown`.

Готово, когда: ни одно из трёх не компилируется без проверки, доказывающей форму, и хотя бы один скрытый дефект выходит наружу.

## Частые ошибки

- **Аннотировать всё подряд** — аннотации становятся второй программой, которая расходится с первой; исправить: аннотируйте параметры и экспортируемые возвраты, а локальные переменные оставьте выводу.
- **Оставлять `strict` выключенным** — `null` проскакивает мимо всех проверок, и ошибки во время выполнения остаются; исправить: включите `strict` и исправляйте найденные ошибки по одному файлу за раз.
- **Гасить ошибку через `any`** — проверка перестаёт помогать для этого значения и всего производного от него; исправить: используйте `unknown` и сужайте либо опишите настоящую форму.
- **Тянуться к `as`, чтобы подогнать тип** — приведение отменяет решение компилятора, не меняя значение во время выполнения; исправить: сделайте значение действительно подходящим или проверьте его на границе.
- **Типизировать функцию по её реализации** — тогда вызывающий код зависит от внутренних деталей, и каждый рефакторинг его ломает; исправить: описывайте, что функция обещает, а не как она это делает сейчас.
