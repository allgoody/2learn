## Пример 1 — Отфильтрованный список, сохранённый в состоянии

Поле поиска фильтрует список, и отфильтрованный массив записывается в `ref` наблюдателем. Очистка поля иногда оставляет результаты на экране. Скажите, почему производное значение вообще хранится, затем выведите его вместо этого.

```vue
<script setup>
import { ref, watch } from "vue";

const items = ref([{ id: 1, name: "Настольная лампа" }]);
const query = ref("");
const visible = ref([]);

watch([items, query], () => {
  visible.value = items.value.filter((item) => item.name.includes(query.value));
}, { immediate: true });
</script>
```

### Решение

```vue
<script setup>
import { ref, computed } from "vue";

const items = ref([{ id: 1, name: "Настольная лампа" }]);
const query = ref("");

const visible = computed(() =>
  items.value.filter((item) => item.name.includes(query.value)),
);
</script>
```

Наблюдатель, записывающий второй `ref`, создаёт два источника истины для одного списка, поэтому они могут разойтись — а устаревший отфильтрованный массив это ровно и есть, — и ему нужен флаг `immediate`, чтобы вообще быть корректным на первом рендере. `computed` выводит значение из состояния, от которого зависит, и пересчитывается только при изменении одной из этих зависимостей, поэтому он не может отстать. Шаблон остаётся тонким, у логики фильтрации одно место, и, поскольку это чистая функция реактивного состояния, её можно тестировать отдельно. Побочные эффекты вроде сохранения в хранилище или логирования — вот для чего нужен `watch`.

## Пример 2 — Список с ключом по индексу

Строки редактируемого списка получают ключ по своей позиции. Удаление первой строки оставляет введённые заметки при не тех элементах. Объясните, что ключ сообщает фреймворку, затем задайте ключ по чему-то стабильному.

```vue
<template>
  <ul>
    <li v-for="(item, index) in items" :key="index">
      <input v-model="item.note" />
      {{ item.name }}
    </li>
  </ul>
</template>
```

### Решение

```vue
<template>
  <ul>
    <li v-for="item in items" :key="item.id">
      <input v-model="item.note" />
      {{ item.name }}
    </li>
  </ul>
</template>
```

Ключ — это то, как фреймворк сопоставляет отрисованный элемент данным, из которых тот появился, поэтому индекс говорит «то, что стоит на первой позиции»: после удаления или переупорядочивания на первой позиции оказывается другой элемент, и фреймворк переиспользует поле ввода, которое уже было там, вместе с введённым в него текстом. Ключ по стабильному id позволяет элементу следовать за своими данными, поэтому удаление строки убирает нужную, а локальное состояние каждой другой строки остаётся у своего владельца. Берите для ключа идентичность из предметной области и никогда позицию в массиве, когда список может меняться или переупорядочиваться. `v-if` и `v-show` — отдельный выбор: один создаёт и уничтожает поддерево, другой лишь скрывает его.
