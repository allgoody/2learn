## Пример 1 — Ребёнок, меняющий переданный ему prop

Компонент-счётчик увеличивает полученное значение, и отображение у родителя с ним расходится. Скажите, в каком направлении должны идти данные, затем верните изменение родителю.

```vue
<script setup>
const props = defineProps({ count: Number });
</script>

<template>
  <button @click="props.count++">{{ props.count }}</button>
</template>
```

### Решение

```vue
<script setup>
defineProps({ count: { type: Number, required: true } });
const emit = defineEmits(["increment"]);
</script>

<template>
  <button @click="emit('increment')">{{ count }}</button>
</template>
```

```vue
<Counter :count="count" @increment="count++" />
```

Prop — это значение, которым владеет родитель, поэтому ребёнок, пишущий в него, обновляет копию, о которой родитель не знает, и два представления расходятся: ошибка выглядит как проблема отрисовки, а не данных. Контракт — props вниз и события вверх: ребёнок сообщает, что произошло, а родитель решает, каким будет новое значение. Объявление типа и обязательности prop — вторая половина, потому что оно превращает контракт в то, что фреймворк проверяет во время разработки и документирует в файле. Свобода ребёнка от состояния родителя — это ещё и то, что делает его переиспользуемым на следующем экране.

## Пример 2 — Разметка, отправленная в компонент строкой

Карточка принимает свою шапку и кнопки действий как HTML-строки и отрисовывает их через `v-html`. Вызывающие не могут вкладывать компоненты, а один из них сломался, когда в содержимом появилась кавычка. Скажите, чего стоит prop-строка, затем передайте структуру вместо неё.

```vue
<script setup>
defineProps({ title: String, actionsHtml: String });
</script>

<template>
  <section class="card">
    <h2>{{ title }}</h2>
    <div v-html="actionsHtml" />
  </section>
</template>
```

### Решение

```vue
<template>
  <section class="card">
    <header><slot name="header" /></header>
    <slot />
    <footer><slot name="actions" /></footer>
  </section>
</template>
```

```vue
<Card>
  <template #header><h2>Счёт №1042</h2></template>
  <p>{{ summary }}</p>
  <template #actions>
    <Button variant="primary">Оплатить</Button>
  </template>
</Card>
```

Строка разметки разбирается как HTML, поэтому экранирование становится заботой вызывающего, а всё, что в ней пришло от пользователя, — это путь для инъекции; вдобавок она не может содержать другой компонент, и именно поэтому вызывающие хотели возможность, которую карточка дать не могла. Слоты передают структуру как структуру, поэтому собственные компоненты вызывающего, обработчики событий и привязки работают так, как написаны, а карточка остаётся безразличной к тому, что попадает в каждую область: её поверхность стилизации — это её собственные элементы и классы, которые она выставляет, и ограниченное правило корректно не может достать до внутренностей ребёнка.
