## Что это такое

Однофайловый компонент — это один файл `.vue`, который содержит блок `<script>`, блок `<template>` и необязательные блоки `<style>`. Сборочная цепочка компилирует его в обычный компонент на этапе сборки. Этот формат — визитная карточка Vue: три вещи, которые меняются вместе — логика, разметка и стили, — живут в одном файле, а стили можно ограничить элементами этого файла.

## Почему это важно

В совместном размещении весь аргумент. Когда поведение, разметка и стили компонента лежат в одном файле, правка означает открыть одно место, а удаление — удалить один файл. Альтернатива — отдельные каталоги шаблонов, скриптов и таблиц стилей, которые должны оставаться согласованными, — стоит времени на навигацию при каждом изменении и оставляет мёртвые фрагменты, когда компонент убирают. Ограниченные стили добавляют вторую выгоду: имя класса можно переиспользовать в разных компонентах без соглашения об именовании, потому что компилятор переписывает его во что-то уникальное.

## Ключевые идеи

### Контракт компонента: props вниз, события вверх

Родитель передаёт данные через `props` и слушает изменения через `emits`. Ребёнок никогда не изменяет свои props; когда ему нужно что-то поменять, он испускает событие, а решает родитель. Именно это одно направление делает дерево компонентов предсказуемым, и это та же дисциплина, которую каждый фреймворк навязывает по-своему.

```vue
<script setup>
const props = defineProps({
  label: { type: String, required: true },
  disabled: { type: Boolean, default: false },
});

const emit = defineEmits(["submit"]);
</script>

<template>
  <button :disabled="disabled" @click="emit('submit')">{{ label }}</button>
</template>
```

### Props объявляются и проверяются

Объявление типа, обязательности и значения по умолчанию для каждого prop превращает контракт компонента в то, что фреймворк проверяет во время разработки и документирует для всякого, кто откроет файл. Prop, который требуется шаблоном, но не объявлен, — это сюрприз во время выполнения.

### Слоты — так внутрь передаётся структура

Слот — это место, которое заполняет родитель; так компонент принимает разметку, не получая её строкой. Именованные слоты позволяют компоненту-раскладке определить несколько областей — шапку, тело, область действий, — оставаясь безразличным к тому, что в них попадёт.

```vue
<!-- Card.vue -->
<template>
  <section class="card">
    <header><slot name="header" /></header>
    <slot />
  </section>
</template>
```

### Ограниченные стили изолируют без соглашения

Добавление `scoped` к блоку `<style>` переписывает его селекторы так, что они совпадают только с элементами этого компонента. Это убирает нужду в соглашении о префиксах, но также означает, что ограниченное правило не может стилизовать внутренности дочернего компонента — и это скорее свойство: поверхность стилизации это собственные элементы компонента и классы, которые он выставляет.

### Для всего нетривиального предпочитайте composition API

Синтаксис `<script setup>` объявляет логику сверху вниз, без `this`, поэтому функции и импорты читаются по порядку и переиспользуются между компонентами как composables. Старый options API всё ещё работает и часто встречается в существующем коде; новым компонентам идёт на пользу более плоская форма.

## Практика

### Извлеките переиспользуемый компонент

Возьмите блок разметки, продублированный на двух экранах, и извлеките его в однофайловый компонент со props для данных и слотом для изменяемой части.

Готово, когда: оба экрана используют компонент, компонент ничего не знает ни об одном из них, а продублированная разметка существует один раз.

### Ограничьте стили компонента и докажите это

Дайте компоненту имя класса, которое используется и в другом месте страницы, добавьте `scoped` к блоку стилей и посмотрите на отрисованное имя класса в браузере.

Готово, когда: класс переписан в уникальную форму, другой элемент на странице не затронут, и вы можете сказать, до чего область видимости не доходит.

## Частые ошибки

- **Изменение prop внутри ребёнка** — данные родителя меняются без его ведома, и двое расходятся; исправить: испустите событие и позвольте родителю обновить значение.
- **Объявление props без типов или значений по умолчанию** — контракт невидим, и отсутствующее значение падает во время рендера; исправить: объявляйте тип, required и default для каждого prop.
- **Передача разметки строкой через prop вместо слота** — вызывающий не может вкладывать компоненты, а экранирование становится опасностью; исправить: используйте слот.
- **Предположение, что ограниченный стиль достаёт до дочернего компонента** — правило молча не применяется; исправить: выставите значение как пользовательское свойство или стилизуйте публичный класс ребёнка.
- **Обращение к options API в новом коде по привычке** — `this` разбрасывает логику, и composables нельзя переиспользовать; исправить: используйте `<script setup>` для новых компонентов.
