## Что это такое

Состояние — это данные, которые компонент помнит между рендерами. В функциональном компоненте состояние добавляется хуком: `useState` возвращает текущее значение и функцию-сеттер, которая его заменяет. Вызов сеттера планирует новый рендер, и новое значение появляется именно в нём.

## Почему это важно

Без состояния компонент может показать лишь то, что ему передали, поэтому любое взаимодействие — открытое меню, введённый символ, выбранная строка — должно было бы жить в родителе и протягиваться вниз. Состояние оставляет эту бухгалтерию локальной и позволяет React решать, когда перерисовывать. Большинство ошибок React — ошибки состояния: значение, которое никогда не обновляется; две копии одного факта, расходящиеся со временем; сеттер, вызванный из устаревшего замыкания. Понимание того, что на самом деле делает обновление состояния, убирает все три.

## Ключевые идеи

### Состояние — это снимок, а не живая переменная

Каждый рендер захватывает значения, с которыми был вызван. `count` внутри обработчика принадлежит тому рендеру, который создал обработчик, поэтому два вызова `setCount(count + 1)` в одном событии видят один и тот же `count` и прибавляют один, а не два.

```jsx
function Counter() {
  const [count, setCount] = useState(0);

  function addTwo() {
    setCount((c) => c + 1);
    setCount((c) => c + 1);
  }

  return <button onClick={addTwo}>{count}</button>;
}
```

Форма с функцией-обновителем получает ожидающее значение, а не копию из рендера, поэтому она безопасна по умолчанию всегда, когда следующее значение зависит от предыдущего.

### Не храните то, что можно вычислить

Если значение выводится из свойств или другого состояния, вычисляйте его во время рендера, а не храните. Хранение означает вечное согласование двух фактов, и тот, про который забудут, и увидит пользователь.

```jsx
// Так лучше
const visible = items.filter((item) => item.done === false);

// Так не надо — `visible` в конце концов разойдётся с `items`
const [visible, setVisible] = useState(items.filter((item) => item.done === false));
```

`useMemo` используйте только тогда, когда вычисление измеримо дорого, а не для защиты правила, которое вы уже нарушили.

### Держите состояние у его низшего общего владельца

Когда два компонента должны согласованно иметь одно значение, поднимите состояние к их ближайшему общему родителю и передайте значение вниз вместе с колбэком для его изменения. Это называется поднятием состояния. Перемещение его в глобальное хранилище раньше, чем оно вообще понадобилось другим, добавляет косвенность, которую потом нельзя убрать без перепроектирования.

### Правила хуков — цена этой конструкции

Хуки нужно вызывать на верхнем уровне компонента или другого хука — никогда внутри условия, цикла или вложенной функции. React сопоставляет хуки внутренним слотам компонента по порядку вызова, поэтому условный хук сдвигает каждый следующий на единицу и порождает состояние, принадлежащее не той переменной. Правило линтера это обеспечивает; держите его включённым.

### Обновления собираются, затем следует один рендер

React собирает обновления одного события и рендерит один раз. Сеттер не меняет значение текущего рендера, поэтому чтение состояния сразу после установки возвращает старую копию. Это свойство, а не дефект: оно не даёт одному событию породить три несогласованных кадра.

## Практика

### Соберите список с фильтром

Создайте список задач с текстовым полем, которое фильтрует их по мере ввода. Держите задачи и запрос в состоянии, а видимый список выводите во время рендера.

Готово, когда: ввод показывает отфильтрованный список, очистка поля возвращает все строки, и нет ни одной переменной состояния, значение которой — отфильтрованная копия другой.

### Исправьте двойной подсчёт

Напишите компонент с кнопкой, которая должна прибавлять к счётчику два. Сначала реализуйте её неверно, двумя вызовами `setCount(count + 1)`, посмотрите на результат, затем перейдите к форме с функцией-обновителем.

Готово, когда: кнопка прибавляет ровно два, и вы можете одной фразой объяснить, почему первая версия прибавила один.

## Частые ошибки

- **Чтение состояния сразу после установки** — обработчик видит снимок рендера, а не новое значение; исправить: вычисляйте следующее значение из аргумента функции-обновителя, а не читая переменную.
- **Хранение производных значений** — копия расходится с источником, и экран врёт; исправить: вычисляйте во время рендера и запоминайте только то, что измеримо медленно.
- **Копирование свойств в состояние** — последующие изменения свойства игнорируются, потому что состояние хранит своё первое значение; исправить: читайте свойство напрямую или задайте компоненту ключ, чтобы он пересоздавался.
- **Условный вызов хука** — состояние привязывается не к тому хуку, а ошибки всплывают далеко от причины; исправить: вызывайте каждый хук безусловно, а ветвление делайте внутри него.
- **Дублирование общего состояния в двух компонентах** — две копии расходятся, и исправление требует третьего обновления в третьем месте; исправить: поднимите состояние к ближайшему общему родителю.
