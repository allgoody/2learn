## Что это такое

Эффект — это функция, которая выполняется после того, как компонент отрисован, и служит для синхронизации компонента с чем-то вне React: сетевым запросом, таймером, подпиской или заголовком документа. `useEffect` принимает эту функцию и массив зависимостей, говорящий, когда её запускать снова.

## Почему это важно

Рендеринг должен оставаться чистым, поэтому всё, что касается внешнего мира, обязано происходить после рендера, а не во время него. В эффектах живут загрузка данных, подписки и ручная работа с DOM — и там же рождается большинство продакшен-ошибок React. Запрос, завершающийся после размонтирования компонента; два запроса, где побеждает более медленный; эффект, выполняющийся на каждом рендере и перезапрашивающий данные бесконечно, — всё это следствие массива зависимостей, который говорит не то, что имел в виду автор. Освоенные правила превращают этот класс ошибок в то, что можно прочитать прямо на экране.

## Ключевые идеи

### Эффекты выполняются после рендера, а не во время него

Тело эффекта выполняется после того, как браузер отрисовал зафиксированный результат. Этот порядок намеренный: интерфейс уже на экране, поэтому эффект может безопасно начать медленную работу. Не используйте эффект, чтобы вычислить то, что и так есть во время рендера, — для этого служит обычный код в теле компонента.

```jsx
function DocumentTitle({ title }) {
  useEffect(() => {
    document.title = title;
  }, [title]);

  return null;
}
```

### Массив зависимостей — это триггер

Всё, что эффект читает из области видимости компонента, должно быть в массиве. React сравнивает каждую запись с предыдущим рендером через `Object.is`; любое изменение запускает эффект заново. Пустой массив означает «выполнить один раз после первого рендера». Отсутствие массива означает «выполнять после каждого рендера», а это почти никогда не то, что нужно.

```jsx
useEffect(() => {
  const id = setInterval(tick, 1000);
  return () => clearInterval(id);
}, []);
```

### Возвращайте функцию очистки для всего, что запускаете

Функция, возвращённая из эффекта, выполняется перед следующим запуском и ещё раз, когда компонент размонтируется. Очистка таймера, закрытие сокета и отмена запроса — всё это здесь. Без очистки эффект предыдущего рендера продолжает работать со значениями, которых больше нет.

### Загрузке нужна защита от гонки

Два запроса, запущенных подряд, могут завершиться в обратном порядке, и старый ответ перезапишет новый. Лечится это тем, что ответ игнорируется, как только его эффект очищен: `AbortController` отменяет сам запрос, а флаг `ignore` работает там, где отменить нельзя.

```jsx
useEffect(() => {
  let ignore = false;
  setState({ status: "loading" });

  fetch(`/api/search?q=${encodeURIComponent(query)}`)
    .then((response) => response.json())
    .then((data) => {
      if (!ignore) setState({ status: "ready", data });
    })
    .catch(() => {
      if (!ignore) setState({ status: "error" });
    });

  return () => {
    ignore = true;
  };
}, [query]);
```

Моделируйте запрос как небольшой конечный автомат — `loading`, `ready`, `error` — а не как три булевых значения, которые могут противоречить друг другу.

### Эффект, запускающий одно и то же дважды, — это запах

В режиме разработки React выполняет эффекты дважды, чтобы вскрыть отсутствующую очистку. Если это порождает вторую подписку или удвоенный счётчик, настоящая ошибка — в отсутствующей очистке, а не в двойном запуске. Исправляйте эффект, а не подавляйте второй запуск через ref.

## Практика

### Загрузите список с состоянием загрузки и ошибки

Загрузите список с выбранного вами эндпоинта и отрисуйте три состояния: индикатор загрузки, список и сообщение с кнопкой повтора. Добавьте поле поиска, меняющее запрос.

Готово, когда: индикатор появляется при первой загрузке, неудачный запрос показывает сообщение об ошибке с работающим повтором, а быстрый ввод никогда не оставляет список с результатами предыдущего запроса.

### Докажите, что очистка выполняется

Добавьте компонент, который пишет в журнал при монтировании и при размонтировании, смонтируйте и размонтируйте его кнопкой-переключателем, а затем смонтируйте сразу два таких компонента.

Готово, когда: консоль показывает один запуск и одну остановку для каждого монтирования, ни одна остановка не пропущена и ни одна не продублирована.

## Частые ошибки

- **Отсутствующий массив зависимостей** — эффект выполняется после каждого рендера и перезапрашивает данные в цикле; исправить: перечислите каждое читаемое значение или используйте пустой массив, если оно не читает ничего.
- **Забытая очистка** — таймеры, сокеты и подписки продолжают работать после размонтирования; исправить: возвращайте функцию, останавливающую всё, что запустил эффект.
- **Игнорирование ответов, пришедших не в том порядке** — медленный ранний запрос перезаписывает быстрый поздний; исправить: отменяйте через `AbortController` или защищайтесь флагом `ignore`, устанавливаемым в очистке.
- **Вычисление в эффекте того, что относится к рендеру** — лишний рендер и мигание устаревшего результата; исправить: считайте это в теле компонента и передавайте вниз.
- **Один эффект на несвязанную работу** — массив зависимостей смешивает заботы, и несвязанные запуски триггерят друг друга; исправить: разделите на один эффект на каждую синхронизацию.
