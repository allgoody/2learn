## Что это такое

Два ограничения на любую анимацию, которую вы выпускаете. Уменьшенное движение: операционная система предоставляет настройку для людей, которым движение причиняет недомогание или мешает, и `prefers-reduced-motion` сообщает о ней. Производительность: каждая анимация должна укладываться в бюджет кадра браузера, иначе она будет заикаться и заставит страницу казаться сломанной.

## Почему это важно

Движение может вызывать тошноту, головокружение и мигрень у людей с вестибулярными расстройствами, и настройка, которой они об этом сообщают, — та самая, которую ваша таблица стилей обязана уважать. Игнорировать её — не вопрос вкуса: это отказ по стандарту и реальный вред реальному пользователю. Часть про производительность столь же практична: анимация свойства, которое браузер вынужден раскладывать заново, будет дёргаться на телефоне среднего класса, даже если она плавна на машине, где вы её писали, а рывки куда заметнее во время движения, чем при статичной перерисовке.

## Ключевые идеи

### Уважайте настройку уменьшенного движения

Оберните необязательное движение в запрос `no-preference`, чтобы умолчанием был статичный, неподвижный интерфейс. Затем решите, что оставить: изменения прозрачности и цвета обычно безопасны и часто необходимы, чтобы показать, что что-то появилось, тогда как параллакс, крупные сдвиги и зацикленная фоновая анимация должны остановиться.

```css
@media (prefers-reduced-motion: no-preference) {
  .drawer { transition: transform 160ms ease-out; }
}

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
```

Общее правило — это страховка для сторонних виджетов; оно должно лежать под продуманной реализацией, а не заменять её.

### Анимируйте трансформации и прозрачность

Браузер может скомпоновать изменение `transform` или `opacity`, не пересчитывая раскладку и не перерисовывая, поэтому эти два свойства дешёвые. Анимация `width`, `height`, `top`, `left` или `margin` вызывает раскладку на каждом кадре, а анимация цветов — перерисовку. Там, где свойство раскладки действительно должно меняться, анимируйте трансформацию, дающую тот же визуальный результат.

```css
/* дешёво: композитинг */
.row-enter { transform: translateY(0); opacity: 1; }

/* дорого: раскладка на каждом кадре */
.row-enter { height: 2.5rem; margin-top: 0; }
```

### Уводите работу с главного потока, где возможно

Переход или анимация CSS на композитном свойстве идут независимо от JavaScript, поэтому занятый главный поток их не останавливает. Поэтому переход CSS или Web Animations лучше цикла на `requestAnimationFrame`, пересчитывающего позиции каждый кадр.

### Не боритесь с бюджетом кадра

При типичной частоте обновления у вас примерно 16 миллисекунд на кадр, и они делятся со всем остальным, что делает страница. Анимация, запущенная посреди долгой задачи, уронит кадры именно в тот момент, когда пользователь смотрит. Держите анимации короткими, запускайте их после дорогой работы и не читайте свойства раскладки внутри покадрового колбэка.

### Проверяйте с включённой настройкой и с зажатым CPU

Включите настройку операционной системы и убедитесь, что интерфейс по-прежнему работоспособен и понятен. Затем зажмите CPU в инструментах производительности браузера и посмотрите анимацию снова.

Сделанная один раз, эта проверка ловит оба класса отказов раньше пользователя.

## Практика

### Спрячьте одну анимацию за настройкой

Возьмите написанный вами переход и перенесите его за `prefers-reduced-motion: no-preference`. Затем включите настройку и пройдите тот же сценарий.

Готово, когда: сценарий остаётся понятным без движения, и ничто не зависит от завершения анимации для работоспособности.

### Замените анимацию раскладки композитной

Найдите анимацию, меняющую `height` или `margin` на каждом кадре. Перепишите её на `transform` и `opacity` и убедитесь, что визуальный результат тот же.

Готово, когда: запись производительности не показывает работы раскладки во время анимации, а воспринимаемое движение не изменилось.

## Частые ошибки

- **Игнорирование `prefers-reduced-motion`** — часть пользователей страдает от анимации и не может от неё отказаться; исправить: прячьте движение за `no-preference`.
- **Анимация `height` или `margin`** — каждый кадр вынуждает проход раскладки, и на медленном железе анимация заикается; исправить: анимируйте `transform` и `opacity`.
- **JavaScript для покадрового цикла там, где хватило бы CSS** — анимация конкурирует с работой приложения за главный поток; исправить: предпочитайте переход CSS или Web Animations API.
- **Отключение всей обратной связи при уменьшенном движении** — интерфейс становится двусмысленным насчёт того, случилось ли что-нибудь; исправить: оставьте мгновенные смены состояния или только через прозрачность.
- **Проверка только на быстрой машине** — рывки проявляются на железе среднего класса, которого разработчик не видит; исправить: зажимайте CPU при проверке анимации.
