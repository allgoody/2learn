## Пример 1 — Страница, которая так и не заявляет утверждение

Руководство отвечает на частый вопрос, но ответ размазан по пяти абзацам, каждый из которых начинается с оговорки, и суммаризатору нечего выхватить как самодостаточное. Скажите, каким должно быть извлекаемое предложение, затем перестройте страницу, ничего не удаляя.

```text
текущая форма
"Choosing an icon grid"          <- заголовок, не называет вопрос
"Прежде чем решать, стоит помнить, что размеры различаются, и многие команды
 находят, что оптическая согласованность зависит от нескольких факторов, а значит…"
(ещё три абзаца с оговорками, прежде чем появляется рекомендация)
```

### Решение

```text
перестроенная форма
"What grid size should an icon set use?"          <- заголовок называет вопрос
"Внутренняя сетка 24 на 24 держит набор иконок оптически согласованным
 на разных размерах. Более крупные сетки размывают детальные формы,
 когда иконка отрисовывается в 16 пикселей."
(под этим — абзацы с объяснением почему и с исключениями)
```

Суммаризатор выхватывает предложения, которые стоят сами по себе, поэтому абзац, подводящий к мысли через три оговорки, не переживает извлечение, а самодостаточный — переживает. Заголовок тоже часть ответа: именно называние вопроса делает пару «заголовок и первое предложение» полным ответом, а детали под ней затем раскрывают, а не повторяют. Ясность, которая переживает извлечение, — та же ясность, что помогает любому читателю страницы.

## Пример 2 — Одно и то же число в двух местах

Головное число спецификации появляется на странице и, слегка иначе, в структурированных данных. Движки ответов сравнивают страницу с другими описаниями того же предмета, и расхождение читается как ненадёжность. Скажите, чего стоит эта несогласованность, затем дайте числу один дом.

```json
{
  "@context": "<собственный адрес словаря>",
  "@type": "Product",
  "name": "Настольная лампа",
  "weight": { "@type": "QuantitativeValue", "value": "1.8", "unitCode": "KGM" }
}
```

```html
<p>Лампа весит 1.6 kg.</p>
```

### Решение

```html
<p>Лампа весит 1.8 kg.</p>
```

```text
один источник истины: файл спецификации
  проза страницы, структурированные данные и профиль продукта — всё порождается из него
проверяйте копии по расписанию: число, поправленное в одном месте, расходится молча
```

Страница и её структурированные данные — два описания одного факта, и когда они расходятся, система, которая читает оба, не может понять, какому верить, поэтому самый безопасный ответ — обесценить описание. Порождение каждой копии из одного файла убирает этот выбор целиком. Стоит сказать прямо: как движки ответов выбирают цитаты, не публикуется и меняется часто, так что усилие принадлежит тому, где отдача несомненна, — заявлять факты прямо, ссылаться на первоисточники, держать числа согласованными и сначала проходить ворота сканирования, индексации и скорости.
