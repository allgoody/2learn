## Пример 1 — Две неподписанные иконки с противоположными проблемами

Кнопка на панели содержит иконку-лупу, а область статуса показывает иконку предупреждения рядом с текстом. Одна объявляется слишком скупо, другая не сообщает ничего осмысленного. Скажите, что скринридер сообщает для каждой, затем исправьте обе.

```html
<button type="button" class="icon-button">
  <svg viewBox="0 0 24 24"><path d="M10 10l4 4" stroke="currentColor" /></svg>
</button>

<span class="status">
  <svg viewBox="0 0 24 24"><path d="M12 8v5" stroke="currentColor" /></svg>
  Платёж отклонён
</span>
```

### Решение

```html
<button type="button" class="icon-button" aria-label="Поиск">
  <svg viewBox="0 0 24 24" aria-hidden="true" focusable="false">
    <path d="M10 10l4 4" stroke="currentColor" />
  </svg>
</button>

<span class="status">
  <svg viewBox="0 0 24 24" aria-hidden="true" focusable="false">
    <path d="M12 8v5" stroke="currentColor" />
  </svg>
  Платёж отклонён
</span>
```

Кнопка объявлялась как «кнопка» без имени, потому что у элемента управления только с иконкой нет текстового содержимого, откуда взять имя; подпись на элементе управления заставляет его объявляться как «кнопка, Поиск». Иконка статуса — обратный случай: это декор рядом с текстом, который уже несёт смысл, поэтому видимость для дерева доступности вставляет бессмысленное содержимое в порядок чтения — получается «графика», а затем сообщение. Скрытие через `aria-hidden` и `focusable` убирает её из дерева полностью. Правило, решающее, какое исправление применить: дайте имя элементу управления, когда иконка — единственная подпись, и скройте иконку, когда рядом есть настоящий текст. Никогда не подписывайте оба, иначе имя объявляется дважды.

## Пример 2 — Шрифт иконок, который ломается молча

Проект рисует свои иконки из шрифта, и отсутствующий глиф показывается пустым прямоугольником без каких-либо ошибок. Скажите, чего стоит эта модель доставки, затем перейдите к набору символов SVG.

```css
.icon { font-family: "Icons"; font-size: 24px; }
.icon-search::before { content: "\e902"; }
```

### Решение

```html
<svg class="icon" aria-hidden="true" focusable="false">
  <use href="/icons.svg#search" />
</svg>
```

```css
.icon { inline-size: 1em; block-size: 1em; color: currentColor; }
```

Шрифт иконок кодирует каждый глиф как символ из области частного использования, поэтому отсутствующий глиф, неверный кодовая позиция или заблокированный файл шрифта дают один и тот же молчаливый пустой прямоугольник, а шрифт приходится скачивать целиком, чтобы показать одну иконку. Спрайт, на который ссылаются через `<use>`, — это один кэшированный файл символов, которые можно перекрашивать через `currentColor` и задавать размер в `em`, а отсутствующий символ даёт видимую ошибку, а не пустой прямоугольник. Тот же компромисс действует и внутри SVG: спрайт подходит множеству иконок, которым нужны только цвет и размер, а встроенная разметка — верный ответ для немногих, которые должны анимироваться или рисоваться в нескольких цветах.
