## Пример 1 — Один и тот же список классов в четырёх местах

Список классов панели инструментов скопирован в четыре шаблона. Теперь изменение отступа требует четырёх правок, и одну из них в прошлый раз пропустили. Скажите, чего стоит повторение и где должно жить выделяемое, затем исправьте.

```html
<div class="flex items-center gap-2 rounded-md border px-3 py-1.5">
  <span class="text-sm font-medium">Заказы</span>
</div>

<!-- те же двенадцать классов повторены ещё в трёх шаблонах -->
```

### Решение

```jsx
export function Toolbar({ children }) {
  return (
    <div className="flex items-center gap-2 rounded-md border px-3 py-1.5">
      {children}
    </div>
  );
}
```

```jsx
<Toolbar><span className="text-sm font-medium">Заказы</span></Toolbar>
<Toolbar><span className="text-sm font-medium">Счета</span></Toolbar>
```

Когда список утилит повторяется, абстракция — это компонент, а не новый семантический класс: изобретая класс, вы возвращаетесь к проблемам именования и удаления, от которых ушли, но с меньшим инструментарием. Компонент владеет списком в одном файле, носит имя, которое можно произнести вслух, и каждое место вызова передаёт только то, что отличается. Утилиты делают оформление читаемым в точке применения, а граница компонента не даёт этой читаемости превратиться в шаблон, который никто не может проверить. Точка выделения — второе повторение, а не десятое.

## Пример 2 — Имена классов, собранные из строк

Помощник выбирает размер текста, склеивая префикс с переменной, и в собранном выводе стили отсутствуют, хотя в разработке всё работает. Объясните, почему сборка их не видит, затем напишите классы так, чтобы они выжили.

```jsx
function Label({ size = "sm", children }) {
  return <span className={"text-" + size}>{children}</span>;   // text-sm так и не сгенерируется
}
```

### Решение

```jsx
const sizeClass = { sm: "text-sm", md: "text-base", lg: "text-lg" };

function Label({ size = "sm", children }) {
  return <span className={sizeClass[size]}>{children}</span>;
}
```

Сборка обходит исходники в поисках буквальных имён классов и генерирует только найденные правила, поэтому имя, собранное во время выполнения, ничему не соответствует и правило не создаётся. Именно поэтому стиль работает в разработке, где ничего не фильтруется, и пропадает в продакшене. Хранение каждого возможного класса буквально в объекте-словаре даёт сканеру три настоящих имени, сохраняя то же место вызова. Альтернатива — список исключений в конфигурации — работает, но растёт незаметно, и следующий компонент, склеивающий имя из строк, наследует тот же невидимый отказ.
