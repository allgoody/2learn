## Пример 1 — Один и тот же hex-код в одиннадцати шаблонах

Основной цвет продукта записан произвольным значением всюду, где понадобился. Теперь правка дизайна требует одиннадцати изменений, и один оттенок уже чуть отличается. Скажите, чего стоило произвольное значение, затем поместите цвет туда, откуда берутся классы.

```html
<button class="bg-[#0f766e] text-white">Сохранить</button>
<a class="text-[#0f766e] underline">Подробнее</a>
<!-- ещё девять, два из них по случайности #0e756d -->
```

### Решение

```js
// tailwind.config.js
export default {
  theme: {
    extend: {
      colors: { brand: { 50: "#f0fdfa", 500: "#14b8a6", 700: "#0f766e" } },
    },
  },
};
```

```html
<button class="bg-brand-700 text-white">Сохранить</button>
<a class="text-brand-700 underline">Подробнее</a>
```

Утилита, сгенерированная из темы, — это ссылка на токен: `bg-brand-700` означает основной оттенок продукта, поэтому изменение в конфигурации меняет его везде, где он встречается, — именно эта гарантия позволяет подходу «сначала утилиты» пережить редизайн. Произвольное значение несёт только буквальное значение и ничего больше, поэтому палитра дублируется по шаблонам и расходится по одному оттенку за раз. Сохранение числовых шагов фреймворка с одновременной заменой значений даёт каждому разработчику очевидный набор вариантов и убирает всякий повод тянуться за hex-кодом. Используйте `extend`, пока умолчания ещё могут быть в ходу; полностью заменяйте тему только после поиска использования.

## Пример 2 — Палитра, поддерживаемая в двух местах

Файл дизайн-токенов хранит фирменные цвета, а конфигурация фреймворка хранит вручную скопированную версию тех же значений. Релиз меняет файл. Опишите, что произойдёт дальше, затем уберите вторую копию.

```js
// tokens.json
{ "brand": { "700": "#0f766e", "500": "#14b8a6" } }
```

```js
// tailwind.config.js — набран вручную из файла выше
export default { theme: { extend: { colors: { brand: { 700: "#0e756d", 500: "#14b8a6" } } } } };
```

### Решение

```js
// tailwind.config.js — сгенерирован из одного источника
import tokens from "./tokens.json";

export default {
  theme: {
    extend: {
      colors: {
        brand: tokens.brand,
      },
    },
  },
};
```

Две поддерживаемые вручную копии палитры всегда расходятся, и расхождение проявляется как чуть неверный оттенок в одной части продукта, который никто не может объяснить. Генерация темы из источника токенов делает этот файл авторитетным: цвет меняется в одном месте, и сгенерированный класс меняется вместе с ним, без единой правки в конфигурации. Это ещё и держит тему честной насчёт того, что она представляет: проектное решение и значение живут вместе, а изменение темы затем проверяется как визуальный релиз, а не прячется в обычный коммит, меняющий вид каждого экрана.
