## Что это такое

Подход «сначала утилиты» означает оформлять элемент множеством маленьких классов, каждый из которых делает одно, а не одним семантическим классом, чьё правило делает много. Список классов — это не обходной путь вокруг таблицы стилей, а другое место для тех же решений.

## Почему это важно

Именование — самая медленная часть написания CSS, и именно в нём живёт стоимость сопровождения: `.card` обрастает `.card--compact` и `.card--with-badge`, и через год никто уже не знает, какой из одиннадцати классов карточки безопасно удалить. У утилитарного класса ровно одно определение и один смысл, поэтому ничто не двусмысленно и ничто не остаётся брошенным. Цена платится в разметке, где список классов можно прочитать на месте и где повторение способна поглотить граница компонента. Знать, где должна проходить эта граница, и есть навык; без него подход «сначала утилиты» просто переносит проблему в шаблоны.

## Ключевые идеи

### Список классов и есть правило стиля

Читая `<div class="flex items-center gap-2">`, вы узнаёте всё, что сказало бы правило, прямо там, где оно применяется. Между разметкой и стилями нет посредника, и не нужно искать по коду, где определён `.toolbar`.

```html
<div class="flex items-center gap-2 rounded-md border px-3 py-1.5">
  <span class="text-sm font-medium">Заказы</span>
</div>
```

### Выделяйте компонент, а не класс

Когда список классов повторяется, решение — компонент, который им владеет, например `Toolbar`, чья реализация и есть этот список, а не новый утилитарный класс. Тогда у абстракции есть имя, место и причина, а изменение вносится в один файл.

```jsx
export function Toolbar({ children }) {
  return (
    <div className="flex items-center gap-2 rounded-md border px-3 py-1.5">
      {children}
    </div>
  );
}
```

### Утилиты складываются, каждая по своей оси

`p-4` задаёт отступ, `text-sm` — размер шрифта и высоту строки, `md:flex` включает flex-раскладку начиная с точки останова. Варианты собираются одним и тем же синтаксисом модификаторов во всех категориях, поэтому, выучив один префикс — адаптивный, состояние, тёмная тема, — вы знаете шаблон для всех остальных.

```html
<button class="rounded bg-teal-700 px-3 py-1.5 text-sm text-white hover:bg-teal-600 disabled:opacity-50">
  Сохранить
</button>
```

### Порядок задаёт фреймворк, а не файл

Утилиты генерируются в фиксированном порядке, поэтому два класса, задающие одно свойство, разрешаются предсказуемо и не зависят от того, где их написали. Это убирает борьбу специфичностей — и заодно отнимает возможность починить конфликт, переставив правило; таков принимаемый компромисс.

### Произвольные значения — путь отхода, а не привычка

`w-[42ch]` и `bg-[#0f766e]` существуют для единственного случая, который токен действительно не выражает. Кодовая база, полная произвольных значений, перестала пользоваться дизайн-системой и пишет встроенный CSS с лишними шагами.

## Практика

### Переоформите один компонент утилитами

Возьмите компонент с написанной вручную таблицей стилей и перепишите его только утилитарными классами, затем удалите таблицу стилей.

Готово, когда: компонент выглядит идентично, ни одно правило из старой таблицы стилей больше не подключается, а список классов не повторяется внутри компонента.

### Найдите точку выделения

Возьмите страницу, где один и тот же список из семи классов встречается четыре раза. Выделите компонент, который владеет списком, и используйте его во всех четырёх местах.

Готово, когда: список классов существует один раз, каждое место вызова передаёт только то, что отличается, а у компонента есть имя, которое вы бы произнесли вслух.

## Частые ошибки

- **Повторение одного и того же длинного списка классов** — следующее изменение придётся внести четырежды, а внесут трижды; исправить: выделите компонент, который владеет списком.
- **Изобретение семантических классов внутри утилитарного фреймворка** — вы вернулись к проблеме именования, от которой ушли, но с меньшим инструментарием; исправить: выделяйте компонент.
- **Борьба с утилитой через произвольные значения** — дизайн-система обходится стороной, и согласованность теряется; исправить: добавьте значение в тему или примите шкалу фреймворка.
- **Сборка имён классов конкатенацией строк** — сканер их не видит, и в продакшене стили отсутствуют; исправить: пишите полное имя класса в каждом месте вызова.
- **Складывание всех утилит в разметку без всякой абстракции** — шаблоны становятся нечитаемыми и непроверяемыми; исправить: выделяйте на втором повторении, а не на десятом.
