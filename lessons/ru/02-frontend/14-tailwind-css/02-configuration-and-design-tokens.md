## Что это такое

Tailwind генерирует свои утилиты из темы: набора именованных шкал для цвета, отступов, типографики, скруглений, теней и точек останова. Изменение темы меняет сразу все утилиты, поэтому конфигурационный файл — это и есть то место, где живут дизайн-токены проекта, выраженные как значения, в которые разрешаются имена классов.

## Почему это важно

Без настроенной темы утилиты кодируют вкус автора фреймворка, а не продукта, и все тянутся за произвольными значениями, чтобы получить свой цвет. С темой утилитарный класс становится ссылкой на токен: `bg-brand-600` означает основной оттенок продукта, и изменение этого оттенка в одном месте меняет его везде, где он встречается. Это та же гарантия, которую слой токенов даёт при любом подходе к стилям, и именно она позволяет подходу «сначала утилиты» пережить редизайн, а не быть переписанным.

## Ключевые идеи

### Определите шкалу один раз, в теме

Замените палитру по умолчанию палитрой продукта и назовите шаги шкалы так, чтобы намерение было видно. Сохранив числовые шаги фреймворка (`brand-500`, `brand-600`), но заменив значения, вы даёте каждому разработчику очевидный набор вариантов и отбиваете всякий повод тянуться за hex-кодом.

```js
// tailwind.config.js
export default {
  theme: {
    extend: {
      colors: {
        brand: { 50: "#f0fdfa", 500: "#14b8a6", 700: "#0f766e" },
      },
      spacing: { gutter: "1.5rem" },
    },
  },
};
```

`extend` добавляет к умолчаниям; полная замена `theme` их убирает. Большинству проектов нужен `extend`, пока они не убедятся, что умолчания не используются.

### Пусть точками останова владеет фреймворк

Адаптивные префиксы генерируются из настроенных экранов, поэтому добавление точки останова один раз делает доступными `md:`, `lg:` и остальные. Использование настроенного набора, а не произвольных ширин, держит медиазапросы согласованными по всему приложению.

```html
<div class="grid grid-cols-1 gap-gutter md:grid-cols-2 lg:grid-cols-3">
```

### Генерируйте только то, что используется

Сборка обходит исходники в поисках имён классов и генерирует только найденные правила. Поэтому динамическая сборка — `"text-" + size` — не даёт стилей вовсе: сканер работает с буквальным текстом. Полные имена классов, выбранные из словаря, — безопасный шаблон.

```js
// Безопасно: каждый возможный класс присутствует в исходнике буквально
const sizeClass = { sm: "text-sm", lg: "text-lg" };
```

### Держите конфигурацию рядом с токенами, которые она представляет

Если дизайн-система уже публикует токены как файл данных или JSON, генерируйте тему из этого источника, а не копируйте значения. Две поддерживаемые вручную копии палитры расходятся, и расхождение проявляется как чуть неверный оттенок в одной области продукта.

### Версионируйте тему вместе с продуктом

Изменение темы — это визуальное изменение каждого экрана. Отнеситесь к нему как к релизу, сверьте с макетами и оставьте прежнюю палитру доступной на один цикл, если миграцию не удаётся завершить одним коммитом.

## Практика

### Замените три произвольных значения записями темы

Найдите три произвольных значения `[...]`, использованных больше одного раза. Добавьте каждое в тему под ключом, называющим намерение, и обновите места вызова.

Готово, когда: произвольные значения больше не встречаются в исходниках, а новые ключи читаются как проектное решение, а не как буквальное значение.

### Сгенерируйте тему из файла токенов

Если файл дизайн-токенов существует, соберите тему фреймворка из него небольшим скриптом; иначе вынесите токены в один файл, который читают и тема, и любой другой потребитель.

Готово, когда: изменение цвета в источнике токенов меняет сгенерированный класс без правки самого файла темы.

## Частые ошибки

- **Произвольные значения для повторяющихся цветов** — у продукта оказывается несколько почти одинаковых оттенков и ни одного места, где их менять; исправить: добавьте цвет в тему и используйте класс.
- **Сборка имён классов конкатенацией строк** — сканер никогда не видит класс, и стиль отсутствует в сборке; исправить: держите полные имена классов в объекте-словаре.
- **Слишком ранняя полная замена темы** — удалённые умолчания всё ещё используются в углу, который никто не проверил; исправить: сначала расширяйте и сокращайте, лишь поискав использование.
- **Поддержка палитры в двух местах** — файл дизайна и конфигурация расходятся; исправить: генерируйте одно из другого.
- **Отношение к изменению темы как к обычному коммиту** — весь продукт меняет вид без проверки; исправить: проверяйте это как визуальный релиз.
