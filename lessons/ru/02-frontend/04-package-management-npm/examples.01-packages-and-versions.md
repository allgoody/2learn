## Пример 1 — Сборка, изменившаяся без изменений кода

Проект объявляет диапазоны в манифесте и никогда не коммитит lockfile. Через месяцы чистая установка даёт другую программу. Скажите, какая строка это вызвала, затем сделайте установку воспроизводимой.

```json
{
  "dependencies": {
    "date-fns": "^3.6.0",
    "chart-kit": "latest"
  }
}
```

```bash
# черновой проект, lockfile не закоммичен
npm install          # заново разрешает диапазоны на сегодня
npm run build        # падает из-за изменения, которого никто не делал
```

### Решение

```bash
npm install          # разрешить один раз, закоммитить package-lock.json
git add package-lock.json
npm ci               # удаляет модули, ставит строго по lockfile
```

Диапазон `latest` означает, что каждая установка может быть другой программой, а `^3.6.0` доверяет каждому релизу 3.x, который опубликует автор. Lockfile записывает точную версию и хеш целостности каждого пакета дерева, включая транзитивные, которые никто не называл, поэтому следующая установка даёт то же дерево, что вы тестировали. Закоммитьте его и используйте `npm ci` в автоматизации: он ставит строго по lockfile и падает, когда манифест и lockfile расходятся, — а это ровно то расхождение, из-за которого эта сборка изменилась сама.

## Пример 2 — Инструментарий, установленный во время выполнения

Линтер лежит в `dependencies`, поэтому производственная установка тянет его за собой. Отдельно в дереве оказались две копии библиотеки состояния. Разберитесь с обоими и исправьте их.

```json
{
  "dependencies": {
    "react": "^19.0.0",
    "eslint": "^9.0.0",
    "state-lib": "^4.0.0"
  }
}
```

```bash
npm ls state-lib
# state-lib@4.0.0
# state-lib@3.2.1   <- подтянута peer-зависимостью плагина
```

### Решение

```json
{
  "dependencies": { "react": "^19.0.0", "state-lib": "^4.0.0" },
  "devDependencies": { "eslint": "^9.0.0" }
}
```

```bash
npm explain state-lib      # назвать родителя, который подтянул 3.2.1
```

`dependencies` нужны, чтобы приложение работало, а `devDependencies` — чтобы собрать или протестировать его, поэтому линтер в первом разделе заставляет каждого потребителя ставить весь инструментарий ни за чем. Дубликат — более серьёзная половина: две копии библиотеки состояния означают два независимых хранилища, и компонент, читающий старое, не увидит обновление, записанное в новое. `npm ls` и `npm explain` называют родителя и объявленный им диапазон, что превращает непонятный дубликат в конкретный пакет, который надо обновить или заменить, а не в lockfile, который надо удалить.
