## Пример 1 — Бэклог, упорядоченный по тому, кто попросил последним

Бэклог из двадцати элементов лежит в том порядке, в котором его набирали, — ниже его первая десятка. Переупорядочьте её по ценности. Причину позиции дайте каждому элементу в один оборот, держа детали близко к нескольким верхним.

```text
1. переделать страницу настроек         (просит CEO)
2. исправить ошибку округления в счёте  (просит поддержка, ежедневно)
3. добавить выбор эмодзи                (просит один продавец)
4. массовый экспорт заказов             (просят три клиента)
5. страница статуса возврата            (просит поддержка, еженедельно)
6. сохранённые способы оплаты           (просит крупнейший клиент)
7. архивировать старые проекты          (просит одна команда)
8. исправить тайм-аут входа             (просили в прошлом месяце)
```

### Решение

```text
1. исправить тайм-аут входа          блокирует каждую сессию
2. исправить округление в счёте      неверные деньги, видно ежедневно
3. сохранённые способы оплаты        крупнейший клиент, названная потребность
4. страница статуса возврата         еженедельная нагрузка поддержки, готово
5. массовый экспорт заказов          три клиента, требует уточнения
6. архивировать старые проекты       одна команда, умеренная ценность
7. переделать страницу настроек      косметика, без свидетельств
8. добавить выбор эмодзи             один проситель, без свидетельств
```

Новый порядок говорит, какие элементы уточнены достаточно для прогноза, а какие остаются заглушками, — в этом и состоит работа списка. Исходный порядок кодировал очерёдность поступления, а не ценность, поэтому команда выбрала бы сначала выбор эмодзи: он маленький. Однако уточнять все двадцать заранее не стоит — детали заслуживают несколько верхних, а остальные должны оставаться написанными грубо, пока не поднимутся наверх.

## Пример 2 — Один элемент, заполняющий весь спринт

Элемент оценён как целый спринт сам по себе. Разбейте его на части, каждую из которых можно продемонстрировать. Скажите, что происходит с частью, которую команда не успевает закончить.

```text
Элемент  "массовый импорт заказов из файла"
         оценка: весь двухнедельный спринт
```

### Решение

```text
A  разобрать CSV и показать строки, которые он импортирует (демо: загрузка, строки)
B  импортировать проверенный файл и сообщать об ошибках по строкам (демо: смешанный файл)
C  обрабатывать XLSX наравне с CSV (демо: загрузить таблицу)
Незавершённое: C не закончен -> возвращается в бэклог продукта, переупорядочен
               выше D и назван на обзоре спринта.
```

Каждая часть демонстрируется независимо, поэтому спринт заканчивается инкрементом, а не ставкой «всё или ничего». Незавершённая часть возвращается в бэклог продукта заметно, а не переносится тихо. Эта заметность и есть суть: перенос прячет закономерность — элементы слишком велики. Ловушка — дробить по техническим слоям, где ничего нельзя продемонстрировать до приземления последней части.
