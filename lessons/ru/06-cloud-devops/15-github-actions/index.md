## Что это такое

GitHub Actions — система автоматизации, встроенная в GitHub. Рабочий процесс — это файл в репозитории, описывающий, что должно произойти при некоем событии: push, pull request, расписание, — и платформа выполняет его на предоставленной ею машине. Тот же механизм покрывает непрерывную интеграцию, релизы, плановое обслуживание и рутинные работы, поэтому это часто первый конвейер, который берёт в руки команда.

## Почему это важно

Конвейер живёт рядом с кодом, рецензируется как код и не требует отдельного сервера. Для открытого проекта или небольшой команды это решающее преимущество: нечего патчить на раннере, не нужно раздавать учётные данные второй системе, а проверки появляются в pull request'е там, где ревьюер уже находится. Платой становятся зависимость от хозяина сервиса и его раннеров, а также модель оплаты, которая делается значимой в приватных репозиториях с тяжёлым использованием. Понимать, где этот компромисс перестаёт быть выгодным, — то же суждение, что и для любого хостингового сервиса.
