## What it covers

Software development is the whole discipline of turning a need into working software and keeping it working. The three seed names are one field seen from three angles: building software (the craft and the code), delivering an application (the work of getting it into use), and the software development life cycle (the phases from requirements through maintenance). None of them names a single learnable skill, which is why this page exists rather than a lesson.

## Why it matters

Almost every expensive failure in the field is a failure at a boundary between these angles. A well-written component that nobody specified; a specification nobody tested against; a release nobody documented. Knowing what each part of the discipline is responsible for is what lets you notice when one of them has been skipped — and it is why this page points at six entries rather than one.

## Included skills

- **Clean Code** (`01-cs-fundamentals/08-clean-code`) — code that the next person can read and change safely.
- **Unit Testing** (`01-cs-fundamentals/10-unit-testing`) — the tests that make change and refactoring safe.
- **Software Architecture** (`01-cs-fundamentals/25-software-architecture`) — the decisions that are expensive to reverse.
- **Agile Methodology** (`04-product-process/02-agile-methodology`) — planning and delivering under uncertainty.
- **Requirements Engineering** (`04-product-process/05-requirements-engineering`) — capturing what the system must do, testably.
- **Technical Writing** (`04-product-process/08-technical-writing`) — documentation a stranger can follow.

## Where to start

Start with Software Architecture and Clean Code to understand the shape of the thing you are building, then Unit Testing, which is what makes the shape changeable. Move on to Requirements Engineering to see how the work is agreed, and Agile Methodology for how it is delivered in short cycles with feedback. Technical Writing runs alongside them: it is how each decision survives the person who made it.
