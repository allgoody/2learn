# Project Rules: 2learn

## Tech Stack
- Content repo is Markdown only. Node 24.14.1 and npm 11.11.0 are available, but there is deliberately **no `package.json` and no dependencies** in this repo.
- The content validator is plain Node ESM with zero dependencies: `tools/validate-content.mjs` (checks V1–V16 after Plan A's WP-10; `node --check` clean). It runs on a clean checkout with nothing but Node ≥ 22. `TOPICS` holds the eight **prefixed** directory names, so `--topic` needs `03-design-ux` and an unprefixed name silently selects nothing (`0 present`).
- Planned site (a separate plan, in `astro/`): Astro 7.3.8, @astrojs/react 7.0.1, Tailwind CSS 4.3.3, TypeScript 7.0.2, Pagefind 1.5.2. Verified on npm 2026-02-14 — re-verify before installing.
- Astro 7 content layer: `glob({ base: './lessons', pattern: '**/*.md' })`, entry ids derived from the path, served through `getCollection()` and `getStaticPaths()`. Hide `/pagefind/pagefind.js` from Vite at runtime with `new Function("s","return import(s)")`, because Vite rewrites variable imports into its preload helper.

## Architecture
- **Content first.** The lesson corpus is written and validated before any site code exists.
- `lessons/<topic>/<slug>/index.md` is the unit of content; `NN-<slug>.md` children exist only where the tier calls for them.
- `seed/` is the read-only archive of the original skill list (8 topic files plus `skills.md`). It is never edited.
- The 8 topics are: frontend, cs-fundamentals, cloud-devops, backend-data, design-ux, product-process, security, soft-skills.
- The website lives in `astro/` at the repo root and consumes `lessons/` through the content layer, so the corpus stays liftable into its own repository.
- Index files are **generated** from metadata (`node tools/validate-content.mjs --write-index`), never hand-maintained. Hand-written index counts are what drifted in the original seed list.
- `lessons/` (403 files) and `tools/` (2 files) **are tracked in git** — committed through `b362edd`, so `git status`, `git diff --numstat` and `git checkout` all work inside the corpus. The older note that they were untracked is obsolete. The one-off per-WP plan files live outside the repo's review surface: `.pi/plans/**` is tracked too, so a new plan directory shows up as untracked until the user commits it.
- Phase status: **the content corpus is complete; Plan A is mid-execution.** Phases 1 and 2 of `.pi/plans/corpus-order-and-examples/` are done and verified, and Phase 3 is part-written (WP-12/13/14 complete, WP-15 5 of 11 files). `lessons/` is renumbered: 8 prefixed topic dirs, 401 lesson files, ids like `01-cs-fundamentals/12-git`. `node tools/validate-content.mjs` reports `177 present, 0 pending, 31 examples, 266 examples pending, 0 error(s)`. `lessons/INDEX.md` is generated by `--write-index` — never hand-edit it.
- **Two plans exist.** `.pi/plans/corpus-order-and-examples/` (7 phases, 50 WPs) is **mid-execution**; `.pi/plans/russian-corpus/` (8 phases, 41 WPs) is **not started** and must run only after Plan A is fully green, because it mirrors Plan A's final paths (698 files under `lessons/ru/`). Topic order: `01-cs-fundamentals, 02-frontend, 03-design-ux, 04-product-process, 05-backend-data, 06-cloud-devops, 07-security, 08-soft-skills`; entry dirs are `NN-<slug>` and the prefix is part of the id.

## Content Rules
Defined in `lessons/AUTHORING.md` and enforced by `tools/validate-content.mjs` (checks V1 to V14):
- Three body shapes only: full lesson (6 headings, 450-950 words), track landing (5 headings, 200-400 words), area page (4 headings, 120-300 words). `## Core ideas` holds 3-6 `###` subheadings — the upper bound is the one that gets violated; budget five or six.
- Tier determines the child count and is fixed: small 0, medium 2, large 4, area 0.
- Frontmatter field order: title, type, topic, tier, status, aliases, prereqs, related. `prereqs` must equal the inventory exactly — the graph is given, not chosen.
- Child lessons carry exactly two keys, `title` then `prereqs`.
- Prose uses British English; titles are verbatim from `tools/inventory.json`, including `Javascript`, `Restful API` and `Prioritization`.
- **No external URLs anywhere under `lessons/`.** "Go deeper" bullets point at other entries only.
- Batch writers always write `status: drafted`; only the user promotes an entry to `reviewed`.
- Alias, prereq and tier values come from `tools/inventory.json` and nowhere else — a work package that asks for an alias the inventory does not list has not been updated since the inventory was frozen; the inventory wins.
- `## Prerequisites` bullets are written **with backticks** (`- **Title** (\`id\`)`) even though `AUTHORING.md` §5 shows them without; the validator's V10 regex requires the backticks. The Phase 1/2 exemplars confirm this.
- **Worked examples live in sidecar files, never in a lesson body.** A pointer line in `## Practice` is impossible: 20 full-shape lessons sit at 930–950 of the 950-word ceiling and 4 are at exactly 950, so any added line fails V5. The contract is one non-frontmatter file beside the lesson — `examples.md` beside `index.md`, `examples.NN-slug.md` beside `NN-slug.md` — holding 1–2 `## Example N — …` sections, each with one `### Solution`, a language tag on every fence and 120–450 words. Landing and area indexes get none, because they have no `## Practice`. The generated `INDEX.md` carries the link. The contract is written down in `lessons/AUTHORING.md` **§12** (added by WP-9) and enforced by **V15** (shape: no frontmatter, 1–2 `## Example N — …` headings, exactly one `### Solution` each, a tagged fence on both sides of each Solution, 120–450 words, no external URL) and **V16** (coverage: a full-shape lesson with no examples file counts as pending, an orphan or misnamed examples file is always an error). The summary line is now five-part: `X present, Y pending, Z examples, W examples pending, E error(s)`.

## Active Constraints
- Temp/working files MUST be created in `.tmp/` under the repo root, never in system `/tmp/` or outside the workspace. `.tmp/` should be in `.gitignore`. Clean up with `rm -rf .tmp/` after use.
- Never edit `.pi/plans/**` while executing a plan, and never edit `seed/**`.
- Do not commit, and never publish to a remote — the user handles all git history.
- No new dependencies in this repo. The validator must run on a clean checkout with nothing but Node.
- The 13 merged umbrella seed entries (cloud six, UI/UX four, software-development three — a net reduction of 10) exist only as `aliases` on 3 area pages. Do not create directories for them.
- `.pi/` must stay tracked (12 files); it is deliberately not in `.gitignore`. Only `.tmp/` is ignored.
- **A scripted id sweep must exclude `.pi/**` and `lessons/INDEX.md`.** `.pi/CONTEXT.md` and the older plan files contain backticked id-shaped tokens (`frontend/css`, `9/35`) that a naive sweep would corrupt; `INDEX.md` is regenerated instead of edited. Inside `lessons/`, every backticked id-shaped token is exactly one of the 177 entry ids or 224 child ids — verified, no strays.
- **A rename sweep over `lessons/` is reversible, but make a copy anyway.** The corpus is tracked in git, so `git checkout` restores it; a `.tmp/` copy is still worth making because it is what the byte-exact "only ids changed" audit compares against. The largest number of id-bearing lines in any single lesson file is 10, so `git diff --numstat` showing more than 15 changed lines in a file means prose moved, not just ids.
- **Run `--write-index` and `--strict` only in the work packages that say to.** Plan A's WP-6, WP-7, WP-8, WP-10 and WP-11 run them deliberately; every other WP uses the plain `node tools/validate-content.mjs` run. `--strict` currently reports one `[V16]` error per missing examples file (266 remaining) — expected until Phases 3–6 finish.
- **`.tmp/lessons-backup/` must survive until Phase 7** (WP-48 compares against it byte for byte; WP-50 deletes it). `.tmp/` holds only `.tmp/lessons-backup/` — no scratch scripts may be left behind, and `.tmp/renumber.mjs` / `.tmp/rewrite-ids.mjs` are already deleted (WP-8).

## Lessons
- **Recompute file counts per work package; never estimate them.** The first draft of the plan carried 4 wrong "create these N files" counts and 4 wrong per-topic totals (53 against 63, 44 against 59, 44 against 53, 96 against 88). The formula is entries plus medium times 2 plus large times 4.
- **`present` counts inventory entries, not files.** Children (`NN-*.md`) are not entries, so writing a 3-file entry raises `present` by 1. Reading `26 present` as 4 short of 30 was a miscount on my part, not a validator bug — verify with a script before reporting a discrepancy.
- **Budget a full lesson at ~850 words, not 950.** Across Phase 3, most substantial child lessons came in 5–15% over the ceiling on first write and needed a trim sweep; the worst (`git/02-the-daily-workflow.md`) was 1101 words and lost a whole core idea. Writing shorter costs less than trimming, and trimming risks the two formatting mistakes below.
- **A trim edit whose `oldText` ends with a newline can join the last bullet to the following `##` heading.** Symptom: `V7`/`V4` still passes but the file renders wrong, and the blank line before the next heading is gone. Always `tail` a file after a trim sweep.
- **Success checks written as `grep '^- .+ (`id`)'` over a landing page also match the `## Prerequisites` bullets**, because those use the same shape. A plan expecting `2` such bullets in each of three testing entries is arithmetically wrong: the two landings whose prereq is a testing entry score 3, and only the one whose prerequisites read `None.` scores 2. Print the matching lines before treating a mismatch as a defect.
- **The no-external-URL rule catches even illustrative examples — it has now bitten three times.** Phase 2 lost a `schema.org` context value and a canonical-URL example; Phase 3 lost an `export API_BASE=https://api.example.test` shell example. Where an example genuinely needs a URL, use placeholder text and say why in one line. Always grep before declaring a work package done.
- **Area and landing word budgets are tight.** Five `Included skills` bullets cost ~80 words before any prose; three area/landing files exceeded 300/400 words on first write and had to be trimmed. Target ~270 words for an area page.
- **Plan expected values can be arithmetically wrong.** Confirmed errata so far: WP-5 expected `2 present, 29 pending` where only `1 present, 30 pending` is correct; WP-3 expected a "title mismatch" diagnostic no unknown directory can produce; Phase 3's verification expected a global `58 present, 119 pending` where the correct value is `59, 118`; WP-14's cross-reference grep expects `2` where the correct values are `2 / 3 / 3`; Phase 4's verification expects `81 present, 96 pending` where the correct value is `82, 95`; Phase 5's expects `100, 77` where the correct value is `101, 76` (and its Prerequisites section repeats Phase 4's wrong number). The global counts are one low in Phases 3–5 only (59, 82, 101); Phases 6, 7 and 8 matched their plan files exactly (144, 161, 177). Always compare against the documented sequence 59, 82, 101, 144, 161, 177 rather than trusting a plan file's number. Run the check, do the arithmetic, and report the erratum rather than bending the code to match it.
- **The single most common first-draft defect is a seventh `###` subheading in `## Core ideas`** — 14 of the 17 validator errors raised across Phases 4 and 5 were `[V7] Core ideas has 7 subheadings, expected 3-6`. The fix is to delete the heading line so the paragraph joins the neighbouring section, which must be chosen to read as a continuation. Two further errors were `[V5]` bodies of 974 and 991 words against a 950 ceiling; both were trimmed by deleting a heading plus one redundant sentence per overrun.
- **Take every directory slug from `tools/inventory.json`, never from memory or from a paraphrase of the title.** A Phase-5 index was written to `message-queues-kafka-mq/` instead of `message-queues-kafka-rabbitmq/`; V14 reports an unknown directory as an error, so it was caught before the WP check passed, but a rename is cheaper than debugging a missing entry.
- **The validator's Go-deeper bullet pattern does not require a trailing period** (`- **Title** (\`id\`) — text`). A local audit regex that demands a full stop flags bullets ending in `?` as malformed — a false positive. Use the validator's own pattern when sweeping, or verify each hit against `tools/validate-content.mjs`.
- Go-deeper bullet format is only partly enforced: the validator counts bullets that match the pattern and ignores ones that do not, so a malformed bullet silently reduces the count instead of failing. Audit with an `awk` sweep over the `## Go deeper` sections rather than trusting a 0-error run.
- The pi path guard rejects bash commands containing regex escape sequences (the whitespace and digit character-class shorthands), and also rejects any string that parses as a path outside the working directory — including `'lessons/' + id + '/index.md'` built by string concatenation, and a `node -e` snippet containing a newline escape (reported as `Access to D:\n is blocked`). Use `path.join`, write a `.tmp/` script, or avoid backslashes entirely.
- Writing any Python file into this repo makes ruff create `.ruff_cache/`; remove it before staging.
- A one-off scripted edit sweep must read and write files in binary so line endings are preserved; a naive text-mode rewrite turns a CRLF file into a whole-file diff.
- **The validator does not track fenced code blocks.** A line starting with `## ` inside a fence is parsed as a real `##` heading and breaks V4/V7 — it happened in `product-process/technical-writing/01`, where a README example contained section headings. Indent those lines inside the fence or use a non-`##` marker; `#` alone is safe, because only `^## ` is matched.
- **Every fenced block needs a language tag.** The validator does not check this but markdownlint reports MD040. Audit it with a script that tracks fence state, not with a grep for the bare fence — every closing fence matches that pattern too. Three blocks were written bare across Phases 6 and 8.
- **Avoid inline HTML placeholders in prose.** Writing a user-story shape as `"As a <role>, I want <capability>"` tripped MD033 three times in one file; use `*role*` or plain words instead.
- **Verify every cross-reference id against `tools/inventory.json` before writing it.** `frontend/accessibility` does not exist (the real id is `frontend/accessibility-wcag-a11y`) and `cs-fundamentals/documentation` does not exist at all; two invented ids produced five V7 errors.
- **V6 catches `https://` inside code examples.** A redirect example in `security/https-tls/02` naming an explicit scheme and host was rejected; describe the redirect without the scheme, for example `301 <same host, secure scheme><same path>`.
- **The area-page ceiling is 300 words and it is tight.** `product-process/software-development` landed at 302 on the first draft and needed a targeted trim. Budget about 270 words for an area page; landings (~270) and full lessons (~700-850) were comfortable.
- **Phase 8's `grep -rni 'pending' lessons/*/` check is a substring proxy with false positives.** It matches "depending" and legitimate technical senses of the word — Kubernetes pods left "pending forever", a JavaScript promise's pending state. Read the hits before treating a non-empty result as a defect.
- **The prereq graph is 127 within-topic edges and only 9 cross-topic ones.** A dependency ordering is therefore *derivable*, not a judgement call: the per-topic topological sort resolves 177/177, and areas go first (inventory order), ties broken by inventory order. Only one of the nine cross-topic edges constrains the topic order in each direction tested — `backend-data/sql-relational-databases` → `cs-fundamentals/database-internals` is what makes the fundamentals-first order need a one-line prereq demotion.
- **Do not add a `##` heading to a lesson file to carry new content.** The three body shapes are exact and V4 rejects any extra heading; 297 files would fail at once. A new content type belongs in a separate file whose name the validator's child regex cannot match.
- **`examples.NN-slug.md` does not match the validator's `/^\d{2}-/` child filter**, which is exactly why the naming rule was chosen — `01-x.examples.md` *would* match the filter and corrupt V8's child count. The child filter still ignores examples files; V15/V16 pair each one with its lesson explicitly instead.
- **`id === topic/slug` survives numeric prefixes for free**, because the validator builds ids from directory names; `01-css` already satisfies the existing slug regex. Only the `TOPICS` constant has to change. The `--topic` flag then expects the prefixed name, so `--topic design-ux` starts failing and `--topic 03-design-ux` works.
- **`legacy-ru` in the knowledge bases is the paradise-education blog, not lesson material** — it is not a translation source for this corpus. A quick semantic search confirms it before anyone plans around it.
- **Russian word bands for this corpus are an estimate, not a measurement** (full 400–1100, landing 180–460, area 100–340, examples 100–500). Russian technical prose carries the same content in fewer words than English, but the exact ratio was not measured — tighten the bands only from real counts.
- **The plan's "five id shapes" list was one short: the frontmatter `topic:` scalar.** V3 requires `topic` to equal `inventory.topic`, so WP-3's inventory rewrite broke all 177 `index.md` files at once (`[V3] topic is 'cs-fundamentals', expected '01-cs-fundamentals'`, on top of 177 V1 `unknown topic` errors = 354). The id sweep had to be extended to rewrite that bare topic value — approved by the user mid-run. Any future renumber must treat `topic:` as id-bearing.
- **The 120–450 word band counts fenced code, so a file that reads like ~400 words measures 450–510.** Budget ~380 words in the first draft: 12 of the 31 examples files written so far needed a trim sweep. Trim the least load-bearing sentence of each Solution explanation, then re-measure with the validator rather than by eye (`node tools/validate-content.mjs --topic <dir>` reports the exact count).
- **MD041 fires on every examples file and is expected.** §12 forbids frontmatter and requires the file to begin at `## Example 1 — …`, so there is no top-level `#` heading to add. It is a deliberate, plan-verified deviation — do not "fix" it.
- **The pi path guard rejects `^` followed by a character inside a bash command string**, not only backslash escapes: a `node -e` with `.match(/^## Example/gm)` or a `sed -n '/^## 1\./,/^## 2\./p'` fails with `Access to D:\^## is blocked`. The error looks like a bad regex but is the path guard. Avoid the caret (use `split()` + `startsWith()`), or write the script to `.tmp/`; `String.fromCharCode(10)` substitutes for a rejected `\n`.
- **Keep `--strict` out of the loop during Phases 3–6.** It reports one `[V16]` error per missing examples file (266 remaining, by design). The signal to watch is the five-part summary's `W examples pending`, which must fall by exactly the number of files the work package creates.
