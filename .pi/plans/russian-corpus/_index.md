# Plan: Russian corpus

## Objective

Mirror the whole English corpus into `lessons/ru/`, one Russian file for every English file — 401
lesson files and 297 examples files, 698 files in total — translated by the executor and reviewed by
the user. When this plan is executed, `node tools/validate-content.mjs --strict --lang ru` reports
`177 present, 0 pending, 297 examples, 0 examples pending, 0 error(s)` and exits 0.

## Global Context

**Dependency.** This plan requires `.pi/plans/corpus-order-and-examples/` to be fully executed
first. It mirrors the *final* paths, ids and titles of the English corpus. If the English tree moves
after this plan starts, every Russian path is wrong.

**The project.** `2learn` is a Markdown-only lesson corpus at `D:\coding\apps\2learn` with no
`package.json` and no dependencies. All tooling is plain Node ESM and must keep running on a clean
checkout with nothing but Node ≥ 22.

**The mirror rule.** Every file at `lessons/<relative path>` becomes
`lessons/ru/<same relative path>`:

```
lessons/01-cs-fundamentals/04-database-internals/index.md
lessons/01-cs-fundamentals/04-database-internals/examples.md
  ↓
lessons/ru/01-cs-fundamentals/04-database-internals/index.md
lessons/ru/01-cs-fundamentals/04-database-internals/examples.md
```

No file is renamed, added, dropped or reordered. The Russian tree has the same 8 topic directories,
the same 177 entry directories, the same child filenames and the same examples filenames.

**Ids stay language-free.** A Russian entry's frontmatter carries the *English* `topic`, `prereqs`
and `related` values — `01-cs-fundamentals/04-database-internals`, `02-frontend/29-react`. Only `title` and the
body prose are Russian. The site distinguishes the languages by the path root (`lessons/` vs
`lessons/ru/`), not by a frontmatter field.

**What is translated and what is not.**

| Translated | Left alone |
| --- | --- |
| `title` in frontmatter (index and children) | `type`, `tier`, `topic`, `prereqs`, `related` |
| All prose under every `##` heading | `status` — always `drafted` |
| All `##` headings themselves | `aliases` — copied verbatim from the English file |
| Prose inside code comments and example strings | Code identifiers, keywords, commands, file names |
| The one-line descriptions in `In this track`, `Included skills`, `Where to start` | Ids in backticks |
| The `**Title**` text in every bullet | Fence language tags (`ts`, `bash`, `json`, …) |

**Word bands for Russian.** The English bands cannot be reused: Russian renders the same content with a different word count —
usually fewer words at the lower bound, with headroom for translation expansion above. The validator
uses these bands instead, from WP-2 onwards.

| Shape | Russian band |
| --- | --- |
| full | 400–1100 |
| landing | 180–460 |
| area | 100–340 |
| examples | 100–500 |

## Global Constraints

- **DO NOT** edit anything under `lessons/` outside `lessons/ru/`, except `lessons/AUTHORING.md`
  (extended in WP-3). The English corpus is frozen from the moment this plan starts.
  `tools/validate-content.mjs` is also deliberately extended (WP-1, WP-2), and it sits outside
  `lessons/`.
- **DO NOT** edit `seed/**` or `.pi/plans/**`.
- **DO NOT** `git add`, `git commit`, `git push` or publish anything. The user handles all git.
- **DO NOT** add a `package.json`, a dependency or a lockfile.
- **DO NOT** create a Russian file for an English file that does not exist, and do not skip one that
  does. The mirror is 1:1. Before finishing any work package, compare the file count under
  `lessons/ru/<topic>` with the same count under `lessons/<topic>`.
- **DO** translate the title exactly as `lessons/ru/GLOSSARY.md` gives it. Titles appear in
  `**Title**` bullets all over the corpus; drift there is the failure this plan most needs to avoid.
- **DO** keep every id in backticks byte-identical to the English file.
- **DO** keep code blocks otherwise intact: translate comments and prose strings, never identifiers.
- **DO** keep every fenced block's language tag exactly as the English file has it.
- **DO** keep the em dash (U+2014) and the backticked-id bullet shapes, because the validator
  matches them structurally.
- **DO** write one file per `write` tool call. Never attempt two files in one generation — a long
  single generation is what gets aborted mid-stream and leaves a half-written file.
- **DO** run `node tools/validate-content.mjs --topic <topic dir> --lang ru` after each entry.
- **DO NOT** use the words `https://` or `http://` anywhere under `lessons/ru/`, including inside
  code blocks. This rule has bitten the English corpus three times.
- **DO NOT** use inline HTML placeholders such as `<role>` in prose (markdownlint MD033).
- **DO NOT** put a line beginning with `## ` inside a fenced block — the validator parses it as a
  real heading and the file fails.
- **DO** create temp files only in `.tmp/` under the repo root, and delete them when the phase ends.

## Conventions

- **Frontmatter key order** in `lessons/ru/**/index.md` is identical to the English file:
  `title`, `type`, `topic`, `tier`, `status`, `aliases`, `prereqs`, `related`. A child carries
  exactly `title` then `prereqs`. An examples file has no frontmatter at all.
- **Heading vocabulary** is fixed by the table in WP-3 and enforced by the validator. No synonyms,
  no variants, no trailing punctuation.
- **Russian style**: neutral technical Russian, second person, no marketing adjectives, no
  англицизмы where a normal Russian term exists (see `GLOSSARY.md`). Product names stay in Latin
  script: React, Git, Docker, Kubernetes, Figma, npm.
- **British English** remains the rule for the English corpus; Russian files do not use it at all.
- **Validator runs** are per topic and per language: `node tools/validate-content.mjs --topic
  03-design-ux --lang ru`.
