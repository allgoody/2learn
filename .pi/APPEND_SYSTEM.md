# Project instructions — 2learn

Project-level instructions for pi, appended to the system prompt. They take precedence over
user-level defaults inside this repository.

## Ponytail governs code here; it never governs prose

The ponytail ruleset ("lazy senior dev mode": the smallest complete change, the shortest working
diff wins, deletion beats addition, no abstraction) is a good ruleset for the software projects it
was written for. In this repository it is **in force for code** and **never in force for prose**.

Classify **per edit, by the path of the file you are about to change** — not by the task, and not
by the session. A session here regularly edits both kinds of file in one run, and there is no
single mode that is correct for both.

| The file you are about to change | Ponytail |
| --- | --- |
| `astro/**`, `tools/**`, root config (`lighthouserc.json`, `.gitignore`, …) | **In force.** Take the smallest complete change; delete rather than add; add no abstraction the code does not need. |
| `lessons/**` — the corpus and its contract `AUTHORING.md` | **Not in force.** |
| `seed/**` — the read-only archive | **Not in force.** |
| `content/**` | **Not in force.** |
| `.pi/**` — handoff notes, the rules index, memory chunks | **Not in force.** These are prose meant to be read by a person. |

Why the prose side is excluded: this repository's product **is** prose. `lessons/**` is a
698-file bilingual lesson corpus whose job is to explain a concept to someone who does not know it
yet. Brevity is the failure mode, not the goal. A compressed sentence that sounds authoritative and
teaches nothing is the defect this repository exists to avoid, and it is exactly the defect those
rules push toward. Where a choice is between a shorter explanation and a complete one, take the
complete one.

The contract that governs prose is the repository's own: `lessons/AUTHORING.md`, enforced by
`tools/validate-content.mjs` and `tools/check-ru-style.mjs`. See `.pi/project-rules-memory.md`.

### Say so once, then proceed

Ponytail's mode is a session-wide switch that is not scoped to this repository, so it can be
nominally on while you are writing prose. When that is the case and you are about to make your
**first prose edit of the session**, say so in one sentence in your reply — for example: "note:
the ponytail ruleset is on; `/ponytail off` if you want it out of the way." Then carry on with the
work. The table above already governs, so that notice is information and not a gate: do not block
on it, do not ask a question about it, and do not raise it a second time.

### Never change the mode yourself

The mode belongs to the operator. Do not write ponytail's config or flag files, do not send a
message that deactivates it, and do not edit this file to turn it on or off. The extension
deliberately ignores input that does not come from the operator, and the scoping above is what
makes the mode unnecessary for this repository's prose.
