# CS fundamentals & engineering practice

How software actually works, and how to keep it good.

Part of the [skills index](skills.md). Start here: **Data Structures**, **Algorithms & Big-O**, then the testing section.

## Core computer science

- **Computer Science** — Umbrella for the theory below; not a single skill.
- **Data Structures** — Arrays, maps, trees, heaps: choosing the right one for the access pattern.
- **Algorithms & Big-O** — Sorting, searching, graph traversal and how cost grows with input size.
- **Operating Systems** — Processes, threads, memory, filesystems and scheduling.
- **Computer Networks** — Packets, TCP/IP, ports, DNS and how a request actually travels.
- **Database Internals** — How storage engines, indexes and query planners really work.
- **Concurrency & Async Programming** — Doing several things at once without corrupting shared state.
- **Regular Expressions (Regex)** — Pattern matching for validation, search and text extraction.
- **Pseudocode** — Writing the logic in plain language before it becomes code.

## Code quality

- **Clean Code** — Naming, small functions and readability, so the next reader can change it safely.
- **Code Reusability** — Factoring shared behaviour once, without over-abstracting it.
- **Refactoring** — Improving structure without changing behaviour, in small verified steps.
- **Design Patterns** — Named, proven solutions to recurring design problems.
- **SOLID Principles** — Five rules of object design that keep change local.
- **Code Review** — Reading a diff for correctness, clarity and risk before it merges.
- **Software Architecture** — Choosing boundaries, coupling and trade-offs for the whole system.

## Testing & debugging

- **Unit Testing** — Testing one unit in isolation; fast feedback while coding.
- **Test-Driven Development (TDD)** — Write the failing test first, then the code to make it pass.
- **Integration Testing** — Checking that the pieces work together across real boundaries.
- **End-to-End Testing** — Driving the whole system like a user, to catch what unit tests miss.
- **Playwright** — Modern browser automation for end-to-end and cross-browser tests.
- **Debugging** — Reproducing, isolating and fixing the actual cause rather than the symptom.

## Environment & tooling

- **Git (Version Control System)** — Committing, branching and history; the baseline of collaborative work.
- **Git Branching Strategies** — Trunk-based versus GitFlow, and how a team merges safely.
- **GitHub** — Hosting, pull requests, issues and CI for Git repositories.
- **Unix Shell** — Bash pipelines, files, permissions and environment.
- **Command-Line Interface** — Working fluently in a terminal instead of through GUIs.
